| 编号 | 目标能力 | 最低验收 |

| V2-07 | 可确认的学习计划 | 计划可编辑、排序、确认；重新生成草稿不覆盖已确认版本 |

| V2-10 | 兼容与发布验收 | 保留现有导入、聊天、`/api/assessment/*` 和一次性 Obsidian vault 导入契约 |

## 3. 实现边界

- 无 LLM 时必须提供规则基线；LLM 仅增强摘要、出题、反馈和计划表达。
- 每个知识点、技能映射、评估结论和学习任务必须关联真实来源。
- 评价结果只适用于当前项目，不代表用户整体技术水平或职业能力。
- Obsidian 写回仅修改带系统管理标记且位于授权目录内的文件，并始终要求用户确认。
- 2.0 不提供旧库迁移；用户需要在新数据根中重新导入项目。

## 5. 完成定义

下列定义已由 B-165 本地候选验收覆盖；具体命令、测试数量、原生工具链边界和旧运行时哈希见 v2 readiness。

- Python、Vue / TypeScript 和通用文本三个固定项目完成端到端闭环。
- 未配置 LLM 的规则基线与已配置 LLM 的增强路径均通过对应测试。
- Obsidian 重复事件、离线重放、重命名、删除、路径越界和文件冲突均有可验证行为。
- 旧运行时目录在验收前后保持不变。
- OpenAPI、功能文档、测试指南、发布说明和 Vue 用户文案与实际实现一致。

## 6. 变更规则

- 范围变化必须先更新 B-160 相关需求、设计和 BACKLOG，再进入实现。
- 任何扩大评价口径、写回权限、数据迁移或跨项目能力的提议都需重新评审，不得作为局部实现顺带加入。
