# 项目知识教练

> 状态：Active
> Owner：RAG 团队
> Last Updated：2026-08-01
> Scope：项目分析、定向评估、逐知识点学习、覆盖与技能差距、学习计划
> Related：`retrieval-and-question-answering.md`、`obsidian-integration.md`、`../design/state-flow-and-acceptance.md`、`../design/api-spec.md`、`../adr/ADR-011-interactive-learning-sql-sandbox.md`

## 1. 用户目标

项目知识教练把已导入资料转为可验证的项目理解，形成“有来源问答 → 项目分析 → 定向评估或逐点学习 → 覆盖/差距 → 学习计划”的闭环。评价对象只限用户对当前项目、当前来源版本的理解，不代表职业能力或跨项目等级。

## 2. 当前可达入口

- **教练**：会话、流式问答、来源抽屉，并可从输入工具发起定向评估或逐点学习。
- **学习地图**：项目理解、知识点、项目覆盖、技能映射与最近证据；知识点和有项目证据的技能节点可发起逐点学习。
- **学习计划**：生成草稿、编辑/排序、确认版本、更新确认版进度；确认版 `learning` 任务可开始或继续学习，并可另行发起 Obsidian 发布。
- **学习覆盖层**：在原主视图上展示当前步骤、真实来源、一道练习、历史作答、反馈和服务端允许的下一动作；关闭后保留当前项目与主视图。
- 未挂载的旧 `AssessmentView` 和 `/api/assessment/*` 仅为兼容能力；当前闭环使用 Coach API。

## 3. 项目分析

- 分析只读取已入库资料，不绕过导入层直接扫描磁盘。
- Python、JavaScript/TypeScript、常见清单、Vite 与 Docker 等使用规则分析；其他文本使用 README、目录和高信号资料回退。
- 无 LLM 时规则基线仍可生成概览、稳定知识点和技能映射；LLM 只增强允许的摘要，失败时返回规则结果和 warning。
- 每个结论、知识点和技能映射必须关联同项目真实来源；来源变化或删除后相关分析标记为 `stale`。
- 重新分析创建新运行，不静默改写历史评估或已确认计划。

## 4. 评估与覆盖

- 评估可针对知识点或技能节点发起；作答前不返回参考答案、关键词或评分依据。
- 相同题目和规范化答案可幂等重放，不同答案不能覆盖既有结果。
- 模型评分不可验证时只回退当前题目的规则评分，并明确低置信度。

| 状态 | 分数 | 含义 |
|------|------|------|
| `unassessed` | 无有效评估 | 尚未验证 |
| `needs_work` | `< 0.50` | 当前项目中需要补强 |
| `developing` | `0.50–0.74` | 正在形成理解 |
| `mastered` | `≥ 0.75` | 已有较充分证据 |

- 项目覆盖率是“当前来源版本下已有有效证据的知识点数 / 知识点总数”，不是平均分或掌握率；有效证据可以来自 Coach 评估结果或满足资格的学习 attempt。
- 技能节点只聚合本项目已映射知识点；未验证不能等同低分，无项目证据不能判定掌握或缺失。
- 同一知识点按 `(created_at, id)` 选择最新有效证据。学习 attempt 只有在 `status=evaluated`、`counts_for_mastery=true` 且属于当前分析运行时参与当前覆盖。
- 分析过期后历史评估和学习会话可只读恢复，但不能继续作答；旧 attempt 保留为历史记录，不参与当前覆盖。

## 5. 逐知识点交互学习

### 5.1 启动、恢复与公开范围

- 会话可从教练、学习地图知识点/技能节点或当前确认计划的 `learning` 任务启动，不新增一级导航。
- 新会话只使用当前项目最新且已完成的分析运行。知识点目标生成一个步骤；技能目标按当前项目映射选择最多三个知识点。
- 同一项目和分析运行最多一个未结束会话。同一目标重复启动会恢复原会话；不同目标启动时返回活动会话冲突，客户端恢复服务端最新快照。
- 服务端一次只公开当前步骤、当前 exercise、该步骤历史 attempts、允许动作和真实来源；未来步骤、未启用的巩固题、参考答案与评分依据不提前返回。
- 会话状态为 `ready / learning / awaiting_answer / evaluated / retrying / completed / abandoned`。终态和来源过期会话只读，但界面分别说明完成、放弃或来源已变化。

### 5.2 作答、反馈与重试

- 每次提交保存独立 attempt，不覆盖旧答案；同一会话以 `idempotency_key` 幂等，单调 `version` 阻止旧页面静默覆盖。
- 每步骤达标阈值为 `0.75`，最多三次 attempt。首答和第一次重试使用主问题；第二次仍未达标后启用预生成的巩固题；第三次仍未达标时步骤记为 `needs_work`，仍可继续后续知识点。
- 非 SQL 题使用服务端确定性规则评分；SQL 题只采用沙箱执行和语义检查结果。反馈包含缺失点、语法/安全错误或结果差异，评分失败不能伪装成正确。
- 首次错误后可在仍有重试机会时揭示当前 exercise 的参考答案。揭示后同一 exercise 的后续 attempt 只用于练习，`counts_for_mastery=false`；未揭示的巩固题仍可形成掌握证据。
- 所有步骤都有有效达标证据时会话结果为 `mastered`；揭示后达标可记为 `assisted`，耗尽重试未达标记为 `needs_work`。放弃会话不会删除已保存 attempt。

### 5.3 SQL 练习边界

- 只有知识点真实来源或同 checksum 文档正文中存在可解析的简单 SQLite `CREATE TABLE` 证据时才生成 `sql_query`；普通数据库关键词不会触发 SQL 练习。
- 来源 DDL 只解析为受支持的表、列和关系，不直接执行。练习使用真实表名和列名生成明确标注为练习数据的固定合成样例；只有解析到关系时才生成 JOIN 题。
- 每次评分从结构化 fixture 创建独立临时 SQLite 文件，随后以只读 URI 重开；沙箱不接收 `KnowledgeStore` 连接或正式 `runtime/v2/app.db` 路径。
- 只允许一条 `SELECT` 或非递归 `WITH ... SELECT`。authorizer、进度处理器、扩展禁用、表列/函数白名单及执行和结果上限共同阻断写操作、Schema 读取与资源滥用。
- 评分同时比较规范化结果与必要语义：列名和列顺序必须匹配，`NULL` 与空字符串分离；未要求排序时按保留重复项的多重集合比较，要求排序时比较行序列。

## 6. 学习计划

- 草稿从当前项目覆盖生成，普通任务包含目标、关联知识、真实阅读来源、练习、完成标准、预计时长和状态；来源不足时只能创建明确的补资料任务。
- 新生成只创建新草稿，不覆盖已确认版本；只有最新草稿可编辑结构或确认。
- 确认后结构、顺序、关联和来源冻结，只允许进度在 `todo`、`in_progress`、`done`、`skipped` 间变化。
- 结构哈希和进度哈希用于阻止旧页面静默覆盖；过期分析不能生成或确认新计划，但既有确认版仍可更新进度。
- 只有从当前确认计划的目标任务启动的学习会话会自动联动该任务；教练和学习地图入口只更新掌握证据，不隐式匹配计划项。
- 打开会话不改变进度。首次成功持久化并完成评分的 attempt 将 `todo` 推进为 `in_progress`；所有步骤均取得未揭示答案的有效达标证据后才推进为 `done`。
- 自动联动只修改目标任务并返回最新 `progress_hash`，不改变计划 revision、结构或其他任务；`done / skipped` 不降级，计划脱离当前确认版或来源过期时停止联动。
- 确认学习计划不等于发布到 Obsidian；发布必须另行预览和确认，见 [`obsidian-integration.md`](obsidian-integration.md)。

## 7. 边界

- 不提供团队空间、跨项目能力汇总、职业/JD 评价、绩效或排名。
- 不提供日历排期、提醒、证书、完整 AST 调用图或无需确认的自动发布。
- 不提供通用在线课程、默认 SQL 课程、DML/DDL 练习或连接项目正式数据库的查询练习。
- 默认 v2 数据位于 `runtime/v2/`；不自动迁移或覆盖 1.x 数据。
