# 项目资料导入

> 状态：Active
> Owner：RAG 团队
> Last Updated：2026-08-01
> Scope：项目创建、本地资料导入、增量同步、批次记录与并发边界
> Related：`knowledge-base-management.md`、`github-integration.md`、`obsidian-integration.md`、`../design/api-spec.md`、`../design/database-design.md`

## 1. 用户目标

用户把项目代码、文档和笔记导入独立项目空间，系统将可解析内容保存、分块并建立检索索引。再次同步项目目录时，只重建发生变化的资料。

## 2. 当前可达流程

| 来源 | 当前状态 | 行为 |
|------|----------|------|
| 浏览器文件/文件夹 | 当前可达 | 上传到当前项目，或为文件夹导入创建项目 |
| 文本笔记 | 当前可达 | 保存用户输入的标题与正文 |
| GitHub 仓库 | 当前可达 | 见 [`github-integration.md`](github-integration.md) |
| Obsidian Vault 路径 | 当前可达 | 一次性只读导入，见 [`obsidian-integration.md`](obsidian-integration.md) |
| URL 摘录 | 部分接线 | 资料弹窗只提交 URL，而当前 API helper 还需要标题和正文，不能视为闭环 |
| Notion ZIP、网页抓取预览 | 源码保留但不可达 | 后端与兼容导入组件存在，当前 `LibraryModal` 未提供完整入口 |
| 绑定目录预检/同步 | 源码保留但不可达 | `DocumentImportPanel` 和 API 存在，当前主资料入口未挂载该面板 |

## 3. 导入规则

- 目录同步依据内容 checksum 判断新增、更新和未变化文件；删除的来源会清理对应文档、chunk 与向量索引。
- 单文件解析失败不会让整批资料全部失败；跳过和错误会进入导入结果。
- 分块当前使用固定 `700` 字符窗口和 `80` 字符重叠。已加载的分块环境配置尚未接入实际分块路径，不能描述为可调参数。
- PDF 正文提取按需导入 `pymupdf`；该包不在基础依赖中，未安装时 PDF 会受控降级为不可解析，而不是阻止服务启动。
- 各项目数据隔离；导入不得跨项目复用文档身份。

## 4. 批次与并发

- 导入操作保存批次摘要和条目，记录来源类型、状态、统计、时间、跳过与错误信息；批次不保存原始正文。
- 批次只记录完成后的审计结果，不是可恢复任务队列；重启后不恢复等待中的请求，也不支持取消或自动重试。
- 同一项目的写入型导入通过进程内项目锁串行；不同项目可在线程池中并发执行。
- SQLite 使用 `busy_timeout` 缓解短暂写锁竞争；这不等同于多进程队列或分布式并发能力。
- 批次历史 API 已实现，但当前资料弹窗不展示历史；完整批次列表只保留在未挂载的 `LibraryView`。

## 5. 验收边界

- 修改来源后旧 chunk 不残留；删除来源后旧命中不再返回。
- 同项目的两个导入请求不会同时进入实际写入段，不同项目可以重叠处理。
- 跳过或单文件失败有明确结果，不能把受控跳过统一标为失败。
- 未挂载入口、不可恢复队列和可调分块配置不得写成当前用户能力。
