## 附录：填写示例

下方以包含 HTTP 接口和持久化的订单导出功能为例，并假定项目已启用 `api` 与 `architecture` pack；CLI、库或脚本项目应改写入口类型，并将不适用项填 `N/A`。**复制模板时请删除本附录**。

```markdown
# 订单导出

> 状态：Active
> Owner：张三
> Last Updated：2026-04-17
> Scope：订单中心后台
> Related：`docs/design/api-spec.md`
> Related ADR：ADR-005-export-storage-choice.md

## 1. 功能目标

支持运营同学将筛选后的订单一次性导出为 CSV 或 Excel，替代原有手工复制粘贴。

## 2. 范围

### 2.1 包含内容
- 按筛选条件导出订单列表
- 支持 CSV、Excel 两种格式
- 导出结果异步生成后通过站内信通知下载

### 2.2 不包含内容
- 明细行（订单项）导出，由单独功能承接
- 自动定时导出

## 3. 业务规则
1. 单次导出上限 50,000 行，超过则要求拆分筛选条件
2. 导出任务 7 天后自动清理
3. 导出仅限当前角色可见的数据范围

## 6. 入口与调用方式
| 类型 | 名称 / 命令 / 接口 | 说明 |
|------|------------------|------|
| HTTP 接口 | `POST /v1/orders/export` | 提交导出任务 |
| HTTP 接口 | `GET /v1/orders/export/{id}` | 查询导出任务状态 |

## 7. 实现落点与架构边界
| 能力 / 组件 | 实现位置与职责 | 关键依赖或边界 |
|-------------|----------------|----------------|
| HTTP 入口 | `ExportController`：接收请求并返回任务状态 | 不承载导出规则 |
| 核心逻辑 | `ExportService`：校验条件、创建任务并触发执行 | 通过存储接口访问外部资源 |
| 数据或外部依赖 | `ExportTaskRepository`、对象存储客户端 | 持久化任务记录并写入导出文件 |

## 9. 测试关注点

- 50,000 行边界：49,999 行与 50,001 行两侧的行为差异
- 权限：A 角色导出后，B 角色拿到链接是否仍能下载
- 异常路径：对象存储不可用时任务状态与用户侧提示是否符合设计
- 并发限流：第 3 个与第 4 个任务的不同响应

## 10. 相关决策
- 相关 ADR：`ADR-005-export-storage-choice.md`
- 决策摘要：采用对象存储 + 预签名 URL，避免服务端长连接下载
```
