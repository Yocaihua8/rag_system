## 2. 支持渠道

| 渠道 | 适用场景 | 是否公开 | 负责人 |
|------|----------|----------|--------|
| Issue | Bug、功能建议、文档问题 | 是 | RAG 团队 |
| PR Review | 贡献代码或文档 | 是 / 内部 | RAG 团队 |
| 已确认的私密渠道 | 安全问题、敏感信息泄露 | 否 | RAG 团队 |

## 3. 响应级别

| 级别 | 适用情况 | 首次响应目标 | 处理目标 |
|------|----------|--------------|----------|
| P0 | 安全风险、数据风险、主流程不可用 | TBD | TBD |
| P1 | 重要功能不可用，有明显业务影响 | TBD | TBD |
| P2 | 局部功能异常，有规避方案 | TBD | TBD |
| P3 | 咨询、文档建议、低风险优化 | TBD | TBD |

以上为模板口径，实际 SLA 以项目合同、团队值班规则或维护协议为准。

## 4. 支持范围

支持事项：

- 当前维护版本的缺陷复现、定位和修复建议。
- 已发布能力的使用问题、配置问题和迁移问题。
- 文档缺口、示例错误和可验证的行为不一致。
- 安全问题的私有上报、评估和修复协调。

不支持事项：

- 已停止维护版本的问题修复，除非存在安全或合同要求。
- 未按文档安装、部署或修改源码后产生的不可复现问题。
- 第三方服务、基础设施或客户自定义代码的通用排障。
- 未提供复现步骤、日志、版本号和影响范围的模糊问题。

## 6. 安全问题入口

- 不要在公开 Issue 中发布漏洞细节、密钥、Token、个人信息或可利用路径。
- 通过项目已确认且不会公开报告内容的私密入口上报安全问题；未确认入口前标记为 `TBD`，不要把漏洞细节写入公开 Issue。
- 若启用 `security` 或 `open-source` pack 并已生成专用安全政策，私密入口与处理责任以该政策为准。
- 上报内容建议包含：影响版本、复现步骤、影响范围、临时规避方案、联系方式。
- 若已启用公开漏洞政策 `../../SECURITY.md`、任务跟踪 `../BACKLOG.md` 或发布说明，安全修复过程同步对应文件；未启用的文档不作硬性要求。

## 7. 升级路径

| 场景 | 升级对象 | 需要材料 |
|------|----------|----------|
| 无法复现但影响持续 | RAG 团队 | 日志、时间范围、版本、环境 |
| 疑似安全问题 | RAG 团队；启用专用安全政策后按其中责任人执行 | 私有报告、影响范围、复现步骤 |
| 涉及合同或报价（若有） | RAG 团队 | 合同编号、支持范围、期望时间 |
| 涉及架构决策 | RAG 团队 | 若已启用 RFC / ADR，则提供草案与替代方案；否则按项目实际决策入口记录 |

## 8. 与其他文档的关系

- 若启用了 operations pack 与 `troubleshooting.md`，常见问题排查写入该文档；否则保留在项目现有支持入口。
- 若启用了 operations pack 与 `runbook.md`，长期运行环境的值班、告警和恢复步骤写入该文档；否则按实际运行方式记录或标记 N/A。
- 若启用了 operations pack 与 `../devlog/postmortem-template.md`，事故或复杂排障可据此创建复盘；未启用时使用项目现有复盘入口。
- 若启用了 tracking pack 与 `../BACKLOG.md`，长期改进、技术债和例外处理写入该文件；否则写入项目实际任务管理入口。
