# DevLog 开发日志

> 状态：Active
> Owner：RAG 团队
> Last Updated：2026-07-30
> Scope：Knowledge Island 开发过程记录、年月归档与历史日志索引
> Related：`../README.md`、`../BACKLOG.md`、`../adr/README.md`、`../../CHANGELOG.md`

DevLog 记录开发过程中的实际进展、阻塞、临时决策和下一步，不替代面向用户的发布说明、正式设计或待办管理。

## 1. 定位与边界

| 文档 | 面向 | 内容 | 节奏 |
|------|------|------|------|
| `../../CHANGELOG.md` | 使用者 / 维护者 | 已发布版本的对外变更 | 按版本 |
| `../BACKLOG.md` | 团队 | 待办、已知问题、技术债 | 随时更新 |
| `../adr/*.md` | 团队 | 已接受的重大架构决策 | 按决策点 |
| `YYYY/MM/*.md` | 开发者 / 维护者 | 当天或当周做了什么、卡在哪、下一步 | 日 / 周 |

历史日志是当时事实快照；后续实现变化不回写历史正文。当前事实以源码、活动需求/设计文档、BACKLOG 和 CHANGELOG 为准。

## 2. 目录与命名

- 日期日志放在 `YYYY/MM/`，文件名为 `YYYY-MM-DD.md`。
- 周报仍使用 `YYYY-Www.md`，按该周所在年份和月份归档。
- 同一天多条记录追加到同一文件，不创建后缀副本。
- 模板保留在本目录根：`devlog-template.md`、`postmortem-template.md`。
- 新建日期日志后必须加入 § 3 索引；不得恢复已废弃的 `docs/DEVLOG.md` 聚合文件。

## 4. 使用规则

- 只写过程性事实；定稿设计写入 `../design/` 或 `../adr/`。
- 跨日志仍有效的决策必须提升到 ADR，并在日志中引用 ADR 编号。
- 新发现的问题同步到 `../BACKLOG.md`，日志只保留指针和当时证据。
- 日志保持简短；过长内容拆成正式设计、指南或复盘。
- 日志中的测试结论只代表记录日期和对应提交，不能作为当前验证证据。

## 5. 新建日志

1. 复制 [`devlog-template.md`](devlog-template.md)。
2. 填写真实日期、提交、验证和下一步。
3. 保存到对应 `YYYY/MM/` 目录。
4. 将链接加入 § 3。
5. 运行 `python scripts/check_docs_consistency.py` 和文档链接检查。
