## 1. 当前已识别风险

| 风险 | 触发条件 | 影响 | 缓解 |
|------|----------|------|------|
| 向量化依赖不稳定 | Ollama 未启动或模型缺失 | 导入可降级，但检索体验下降 | 提供关键词检索降级与提示 |
| HTML 注入误伤 | 标准化规则缺陷 | 界面安全风险 | 受控标签白名单 + 转义策略 |
| 兼容层残留 | `Workspace` 与 `Project` 并行 | 语义混淆 | 分级迁移，文档明确边界 |
| 大文件/批量导入性能 | 文件数量激增 | 入库耗时上升 | 进度提示与增量去重 |
| 解析依赖缺失（pdf/docx） | PyMuPDF/python-docx 未安装 | 该类文件跳过 | 明确失败原因 + 持续入库其余文件 |

## 2. Knowledge Island 2.0 残余风险

> B-161～B-165 已完成本地候选实现与自动化验收；下表记录仍需持续约束的触发条件、已落地缓解措施和正式发布门禁，不表示相关风险已经消失。

| 风险 | 触发条件 | 影响 | 缓解 / 验收门禁 |
|------|----------|------|-----------------|
| 1.x、2.0 与正式发布事实混写 | 文档或 UI 仍把当前 2.0 写成未来目标，或把本地候选写成正式发布 | 用户误判能力，验收失真 | 文档和接口测试显式区分“1.x 兼容 / 2.0 当前实现 / 正式发布状态”，发布前逐项核对 |
| 误写或迁移 1.x 数据 | 2.0 复用 `runtime/app.db`、旧向量目录或旧输出目录 | 不可逆数据污染或回退失败 | 强制独立 `runtime/v2/`；命中 1.x schema/path 时拒绝启动；验收前后比较旧运行时文件 hash |
| 来源变化后结论仍显示有效 | 文档修改、重命名或删除后未传播状态 | 知识点、评估和计划依据失真 | 来源 fingerprint/checksum；依赖分析标记 `stale`；重新分析前不显示为最新 |
| 分析器语言盲区 | 非 Python、JS/TS 或清单不完整 | 知识覆盖遗漏或错误映射 | 明确首版支持面；通用 RAG 回退；所有结论附来源和置信度；不把低置信结果写成事实 |
| 评估结果被理解为职业能力 | 项目内得分直接展示为通用能力等级 | 误导学习判断 | 项目知识覆盖为主口径；技能仅从当前项目聚合；明确“未验证”和“评估较弱” |
| 配对码或连接令牌泄露 | 明文持久化、日志记录、过长有效期或路由权限过宽 | Vault 内容被未授权同步或发布 | 一次性限时配对码、哈希存储、Obsidian 路由最小权限、显式撤销、仅 loopback |
| 同步重放与反馈循环 | 断线重试重复提交，生成目录又被反向摄入 | 重复索引、删除或无限循环 | 连接内事件幂等 ID；排除托管输出根；重复事件返回原结果 |
| 路径越界或覆盖用户笔记 | `../`、绝对路径、同名未托管文件或外部编辑 | Vault 数据丢失 | 路径规范化与根目录包含校验；系统标记 + 稳定 ID + hash 三重校验；预览和显式确认；冲突阻断 |
| 插件离线或部分写入 | 确认后插件未轮询、写入中断或结果丢失 | 后端状态与 Vault 不一致 | 不可变发布修订；`queued` 与 `applied` 分离；逐文件原子处理、结果回报和可重试失败状态 |
| Obsidian 启动事件风暴 | 插件在 Vault 初始化期间监听 `create` 并立即全量同步 | 启动变慢、产生重复事件 | `workspace.onLayoutReady()` 后注册事件；批量、去抖和幂等处理 |

## 3. 风险处理优先级

1. 旧数据污染、Vault 路径越界、未授权发布和用户文件覆盖为 P0 门禁，未通过不得发布。
2. 来源陈旧、同步一致性、评估误导和反馈循环为 P1，必须由集成/E2E 场景覆盖。
3. 语言分析覆盖、可选依赖缺失与性能问题为 P2，需提供明确降级并由 BACKLOG 追踪。
