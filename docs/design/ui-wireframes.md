```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ [项目与主导航侧栏]       │ [当前入口主区]                    │ [依据抽屉]     │
│ 当前项目                 │ 教练：会话与下一步学习动作        │ 回答来源       │

│ 设置                     │                                  │                │
└──────────────────────────────────────────────────────────────────────────────┘
```

当前交互契约：

- **教练**是默认入口，复用当前聊天、流式回答与依据抽屉；资料管理和高级工具不铺满主区。
- **学习地图**展示项目理解、知识覆盖、辅助技能差距和评估记录。结论通过统一来源抽屉查看路径、摘录与定位，并注明“仅代表当前项目中的评估结果”。
- **学习计划**展示可编辑、可排序的草稿；确认版结构只读但可更新任务进度。重新生成不得覆盖已确认计划。
- **资料**继续使用弹窗，分别展示插件连接状态与原有一次性只读 Vault 导入。
- **设置**集中管理回答引擎、Obsidian 连接、一次性配对码、输出目录、令牌撤销和高级能力。
- **评估**不是一级入口，从教练工具菜单或学习地图节点打开覆盖层；关闭后返回原上下文。
- **Obsidian 发布**先展示完整 Markdown 与目标路径，再由用户确认；确认后只表示 `queued / 等待插件执行`，最终成功或冲突等待插件回传。

## 1. 当前页面清单

| 入口 | 目标用户 | 主要目标 | 优先级 |
|------|----------|----------|--------|
| 教练（默认首页） | 所有用户 | 围绕当前工作区资料聊天、整理、查看回答依据并发起评估 | P0 |
| 学习地图 | 学习用户 | 查看项目理解、知识覆盖、技能差距、评估记录和真实来源 | P0 |
| 学习计划 | 学习用户 | 生成和编辑草稿、排序、确认、更新确认版进度并预览发布 | P0 |
| 资料（弹窗） | 所有用户 | 加入资料、选择已有资料、查看 Obsidian 连接与一次性导入 | P0 |
| 设置（全屏页） | 所有用户 | 管理回答方式、Obsidian 配对/连接、资料位置和外观 | P1 |

独立一级 `评估/练习` 入口已取消。当前定向评估从教练输入框左下角工具菜单或学习地图知识点/技能节点进入 `CoachAssessmentOverlay`；旧 `AssessmentView` 只保留兼容。

## 2. 布局表达约定

```text
┌─────────────────────────────┐
│  [区域名称]  表示 UI 功能区  │  ← 方括号为区域标签，非代码
└─────────────────────────────┘
```

Vue 主体验采用左侧工作区和线程侧栏，通过 `教练 / 学习地图 / 学习计划 / 资料 / 设置` 切换主流程。`资料` 不切换普通页面，而是打开资料管理弹窗；`设置` 是全屏覆盖页。教练工作台保留左侧工作区/线程、中间对话、右侧依据结构；不复刻多用户、Agent 写操作、Agent Flow 或模型路由。

页面主色采用黑白灰中性方案；错误和警告状态保留必要提示色。外观入口位于 `设置 -> 外观`。

视觉令牌、组件状态、动效和无障碍要求统一见 `codex-ui-visual-system.md`。本文件只定义页面结构与交互，不重复维护样式细节。

## 3. 当前：教练（主页）

**页面目标**：支持多轮对话式 RAG 问答，查看来源和工具结果。

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ [左侧侧栏]                │ [中间聊天区]                    │ [依据抽屉]     │
│ Knowledge Island          │ ┌──────────────────────────────┐ │ 默认收起       │
│ 教练 / 学习地图 / 学习计划│ │ [用户消息]  消息内容          │ │ 回答来源       │
│                            │ │ [AI 回答]  流式 Markdown      │ │ 来源质量       │
│ 工作区                    │ │ [反馈按钮] 有用 / 来源不准    │ │ 检索复盘       │
│ 当前工作区                │ └──────────────────────────────┘ │ 工具结果       │
│ 资料 / 设置               │ [输入框]                        │ 对比回答       │
│ 线程                      │ [+] [快捷工具] [回答引擎] [发送]│                │
│ [搜索线程]                │                                  │                │
│ + 新建                    │                                  │                │
│ ● 第二阶段前端设计        │                                  │                │
│   资料导入问题            │                                  │                │
└──────────────────────────────────────────────────────────────────────────────┘
```

**关键交互**：
- 切换线程后重新加载该线程聊天记录（`GET /api/chat/messages?session_id=`）
- 点击 `资料` 或教练输入框 `+ -> 加入资料` 打开资料管理弹窗，不离开聊天主流程
- 点击教练输入框 `+ -> 练习与小测` 打开 Coach 定向评估覆盖层，不切换到旧评估页
- 发送问题后按钮进入 loading 状态，禁用重复提交，并显示“取消”按钮关闭当前 EventSource 流
- 来源不足时显示建议工具横条，用户点击才触发工具运行（不自动执行）
- 工具运行成功后，可一键引用 `tool_run_id` 到下一轮问答
- 回答通过 `/api/answer/stream` 的 SSE `token` 事件逐步渲染，完成后用 `done` 事件刷新来源、观察性和聊天记录
- 来源、检索复盘、工具结果和对比回答默认进入右侧依据抽屉，不占用中间对话主流程
- 移动端默认隐藏侧栏，只保留顶部菜单按钮；点击后以抽屉显示侧栏

**空状态**：暂无会话时显示"点击 + 新建会话开始问答"引导文案

**错误状态**：API 不可用时显示可恢复提示，说明下一步操作（检查服务 / 刷新）

## 4. 当前：资料弹窗

**页面目标**：让用户先加入资料，再从已有资料中选择需要用于工作区聊天的内容。资料不作为普通主区页面，也不承担问答主流程。

```text
┌──────────────────────────────────────────────────────────────────┐
│ [资料弹窗] 管理资料                                    [关闭]     │
│ [加入库] [选择资料]                                               │
├──────────────────────────────────────────────────────────────────┤
│ 加入库                                                           │
│ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌────────┐ │
│ │ 文件     │ │ 文件夹   │ │ 笔记     │ │ 网页摘录 │ │ 更多来源│ │
│ └──────────┘ └──────────┘ └──────────┘ └──────────┘ └────────┘ │
│ [本次结果] 默认折叠；导入完成或失败后自动展开                    │
├──────────────────────────────────────────────────────────────────┤
│ 选择资料                                                         │
│ 左侧主侧栏切换为“选择工作区”                                      │
│ 右侧显示资料夹、资料列表、加载、错误和空状态                      │
└────────────────────────────────────────────────────────────────┘
```

**关键交互**：
- `加入库` 首屏只展示文件、文件夹、笔记、网页摘录和更多来源
- GitHub、Notion、Obsidian 等高级来源收进“更多来源”；后端未完整支持时只显示说明或复用现有导入事件，不伪造成功
- `ImportResultList` 默认折叠；有导入状态或错误时自动展开
- 点击 `选择资料` 后，主左侧侧栏切换为工作区列表；选择目标工作区不切换当前聊天工作区
- 当前后端仍以 `project_id` 为资料边界，第一版不显示“已连接到多个工作区”这类状态
- Obsidian 区域展示当前项目真实连接、输出目录、同步状态和最近同步时间；未连接时引导到设置生成一次性配对码
- “一次性只读导入”保留为单独区域，明确不会建立插件连接，也不会向 Vault 写回

**空状态**：无资料时提示先用“加入库”上传文件、文件夹、笔记或网页。

## 5. 当前：Coach 定向评估覆盖层与 1.x 兼容

**页面目标**：定向评估不作为一级页面。入口位于教练输入框 `+ -> 练习与小测` 和学习地图节点，使用 Coach API；旧评估组件与 `/api/assessment/*` 只保留兼容。

```text
┌────────────────────────────────────────────────────────────────┐
│  [定向评估] 当前项目知识评估                          [关闭]    │
├────────────────────────────────────────────────────────────────┤
│   这是当前项目中的评估结果，不代表整体职业能力                  │
│   [目标类型：知识点/技能] [评估目标] [开始评估]                │
├────────────────────────────────────────────────────────────────┤
│  [题目区]                                                       │
│   第 1 / 3 题                                                   │
│   ─────────────────────────────────────────────────────────── │
│   请描述 RAG 混合检索的流程，以及关键词检索和向量检索如何合并。 │
│   ─────────────────────────────────────────────────────────── │
│   [答案输入框（多行）]                                          │
│                                                                 │
│                                         [提交回答]               │
├────────────────────────────────────────────────────────────────┤
│  [当前项目评估结果]（提交后显示）                               │
│   发展中 / rule / 置信度 70%                                   │
│   命中证据 / 缺失点                              [查看来源]    │
└────────────────────────────────────────────────────────────────┘
```

**当前实现**：评估可按知识点或技能节点发起并恢复；作答前不显示评分依据，提交后显示状态、评估方式、置信度、命中证据、缺失点与真实来源。状态统一为 `unassessed / needs_work / developing / mastered`，并明确它只描述当前项目中的表现。来源变化后会话转为只读，要求回到学习地图重新分析。

**空状态**：项目尚未分析时提示先打开“资料”导入内容并在学习地图分析当前项目。

## 6. 当前设置页

**页面目标**：全屏管理回答方式、资料保存、备份恢复和外观；技术字段默认收进详情。

```text
┌────────────────────────────────────────────────────────────────┐
│  [顶部导航栏]                                                   │
├────────────────────────────────────────────────────────────────┤
│  [返回] 设置                                                    │
│  [左侧菜单] 回答 / 资料 / Obsidian / 外观                       │
├────────────────────────────────────────────────────────────────┤
│  [回答] 本机回答 / 本机快速 / 在线回答                          │
│        [连接详情] 服务地址、模型名、Key 引用、保存和测试          │
├────────────────────────────────────────────────────────────────┤
│  [资料] 资料保存位置 / 备份 / 恢复                              │
├────────────────────────────────────────────────────────────────┤
│  [Obsidian] 连接 / 配对码 / 输出目录 / 撤销                     │
│  [外观] 深色模式 / 回答方式 / 依据显示                          │
└────────────────────────────────────────────────────────────────┘
```

**关键交互**：
- 测试连接不改变配置，仅验证可达性
- API Key 回显只显示来源引用（`env:DEEPSEEK_API_KEY`），不显示明文
- 每次只展示左侧菜单选中的一个设置页面，不做长滚动设置页
- 当前后端未提供完整资料保存位置迁移、备份恢复桌面能力时，按钮必须显示清楚的不可用或后续支持状态，不伪装成功
- Obsidian 配对页只展示一次性配对码、输出目录和过期时间，不向浏览器返回或保存插件令牌；撤销后刷新当前项目连接状态

高级检索、模型比较与 Agent 审计继续收在高级区域。

## 7. 空状态与错误状态约定

| 场景 | 展示文案 | 下一步引导 |
|------|----------|------------|
| 未创建项目 | "尚无项目空间" | 跳转设置页创建 |
| 项目无文档 | "知识库为空" | 打开库弹窗加入资料 |
| 检索无命中 | "未找到相关来源" | 建议换关键词或补充资料 |
| API 不可用 | "本地服务暂时不可访问" | 提示刷新或检查 `app.py` |
| 在线回答未配置 | "未配置在线回答，使用本地片段回答" | 打开设置页配置连接 |

## 8. B-164 UI 实现与 B-165 本地验收

1. B-164 已实现一级入口 `教练 / 学习地图 / 学习计划 / 资料 / 设置`。
2. 教练保留聊天主区和回答依据；学习地图、计划阅读项和评估结果通过统一来源抽屉打开真实来源。
3. 评估只以覆盖层出现，关闭后保留原页面、输入和当前项目。
4. 学习计划草稿可编辑、排序和确认；确认版只更新进度，发布预览是独立确认步骤。
5. 一次性只读导入与插件连接使用不同状态文案；浏览器不调用插件专用同步、领取或结果回传路由。
6. 发布到 Obsidian 前预览内容和路径并显式确认；确认后显示 `queued` 并等待插件处理，不直接宣称写回成功。
7. B-165/B-166 已完成 Vue 单测、构建、Playwright 主流程、项目教练到 Obsidian 发布的后端全闭环、本地/远端 CI、`main` 合并、Tag、GitHub Release 与 Windows x64 NSIS；证据见 `docs/release/V2_0_0_READINESS_2026-07-24.md`。安装包未签名，macOS / Linux v2 原生产物未运行。
