## 1. 原型门禁

前端采用两轮可交互原型：

| 轮次 | 目的 | 必须确认的内容 | 对生产代码的影响 |
|------|------|----------------|------------------|
| P1 | 低保真信息架构 | 导航、页面层级、任务/审批流程、状态覆盖、响应式面板 | 不允许创建 React 生产前端，不修改 Vue 页面 |
| P2 | 高保真交互与视觉 | 组件、密度、颜色、文案、主题、键盘和完整异常状态 | 用户明确批准后才解除 React 实施门禁 |

两轮原型都使用明确标注的演示内容，不调用真实 API；原型内容不得作为正式应用的回退数据。

## 2. 桌面布局

```text
┌────────┬──────────────────┬──────────────────────────────┬──────────────────┐
│ rail   │ context sidebar  │ main stage                   │ inspector        │
│ 64px   │ 280–300px        │ task / workflow / insights   │ about 360px      │
└────────┴──────────────────┴──────────────────────────────┴──────────────────┘
```

- `>= 1280px`：四区同时显示。
- `900–1279px`：检查器改为抽屉。
- `< 900px`：上下文侧栏和检查器均为可关闭抽屉，主内容保持单列。
- 原型必须在 320px 宽度下仍能访问全部主要动作，不出现内容遮挡。

## 3. 页面覆盖

### Tasks

- 任务列表：新建任务、项目绑定、搜索、状态和最近活动。
- 任务线程：消息、计划、步骤、工具、审批、错误和产物统一时间线。
- 固定输入区：自然语言、快捷动作、Quick/Standard/Deep 和双模型 Compare。
- 检查器：Plan、Sources、Artifacts、Run。

### Project

- Sources/Connectors：本地来源、URL 预览确认、GitHub、Obsidian 和导入结果。
- Project Insights：Overview、Knowledge、Assessments、Learning Plan。
- 项目问答始终面向整个项目；资料选择只浏览和预览。

### Workflows

- 类型化节点目录、DAG 画布、节点配置、校验结果、发布版本和项目绑定。
- 明确展示循环、孤立节点、类型不匹配、缺失参数和写节点缺少审批等错误。

### Settings

- 模型 Profile、双模型可用性、集成、主题、数据根、迁移预检、备份和恢复。
- 密钥只显示“已配置/未配置”和引用，不回显明文。

## 4. 必须覆盖的状态

- 页面：空、加载、部分加载、错误、离线和恢复连接。
- 运行：排队、运行、等待审批、暂停、失败、恢复、完成和取消。
- 步骤：重试、跳过、取消、`recovery_required`。
- 审批：待处理、已批准、已拒绝、已过期。
- 产物：草稿、可预览、导出中、已导出和失败。
- 项目：未选择、无资料、导入预检、部分失败、分析过期。
- 工作流：草稿、无效、有效未发布、已发布和新修订。

## 5. 视觉原则

- 克制、工具化、高信息密度，不复制 AnythingLLM、Codex 或其他产品的品牌视觉。
- 中性表面配单一主强调色，弱阴影，清晰层级；亮色、暗色和跟随系统使用同一语义 token。
- 审批、失败和危险写操作必须同时使用文字、图标和位置表达，不能只靠颜色。
- 使用语义按钮、输入和可访问标签；键盘顺序与视觉顺序一致。

## 6. P1 验收清单

- [ ] 四个一级导航和全部二级页面可达。
- [ ] 可以演示从新建任务到运行、审批、失败恢复和产物的完整路径。
- [ ] 可以演示工作流编辑、校验、发布和项目绑定。
- [ ] 可以切换所有要求的空态、异常态和运行态。
- [ ] 桌面四区和窄屏抽屉行为清楚。
- [ ] 用户明确确认 P1 后才进入 P2。

## 7. P2 验收清单

- [ ] 三种主题、颜色、字体、间距和组件密度获得确认。
- [ ] 所有危险动作和审批信息足以做出判断。
- [ ] 键盘、焦点、320px 窄屏和桌面布局均可完成核心流程。
- [ ] 路由、状态矩阵、组件 token 和交互文案形成冻结的 UI 合同。
- [ ] 用户明确确认 P2 后，才能创建 `frontend-v3/`。
