# 安全与合规规范

> 状态：Active
> Owner：RAG 团队
> Last Updated：2026-07-30
> Scope：Knowledge Island 本地 Web、Tauri、Obsidian Bridge 与 Docker 自托管场景的安全基线和事件响应
> Related：`../../SECURITY.md`、`setup.md`、`runbook.md`、`../design/permission-matrix.md`、`../design/api-spec.md`、`../design/risk-register.md`

Knowledge Island 默认是本地单用户应用。安全边界以实际启动方式为准：本地 `app.py` 默认监听 `127.0.0.1:8765`；Docker 容器监听 `0.0.0.0:8765`，当前 Compose 端口映射未限定宿主机 IP，可能被宿主机网络接口暴露。认证默认关闭，不能把“本地优先”理解为任何部署方式都天然隔离。

## 1. 通用安全基线

### 1.1 资产与可信边界

需要保护的资产包括：

- 用户导入的本地文档、项目知识、聊天记录、评估结果和学习计划。
- 默认 `runtime/v2/app.db`、`runtime/v2/vectors/` 及显式 `RAG_RUNTIME_DIR` 下的数据。
- LLM、Embedding、可选认证使用的 API Key 和 JWT secret。
- 源码、CI 配置、Tag、GitHub Release 和未签名的 Windows 安装包。
- Obsidian Bridge 连接信息和插件可访问的本地内容。

主要不可信输入包括浏览器请求、上传文件、导入路径、文档正文、Markdown、项目导出包、外部 Provider 响应和依赖制品。API 层必须继续校验参数与 `project_id` 边界，存储只通过 `backend/storage/` 访问，Agent 工具保持只读白名单且不得执行 shell。

### 1.2 数据与最小化

- 只导入当前知识库功能需要的文档；不要把无需处理的机密文件放入工作区。
- 默认 SQLite 和向量目录没有已记录的应用层静态加密，机密性依赖主机账号、文件系统权限、磁盘加密和备份保护。
- 配置外部 LLM / Embedding Provider 时，问题、检索内容或文档片段可能发送给该 Provider；使用者必须先确认数据是否允许外发。
- 日志、Issue、PR、测试夹具和截图不得包含真实凭证、完整私密文档或不必要的个人信息。
- 当前没有自动数据保留、过期删除或经验证的整库恢复策略；保留期限和删除要求由数据 Owner 决定。

### 1.3 凭证

- LLM / Embedding Key、`RAG_AUTH_API_KEY`、`RAG_AUTH_JWT_SECRET` 禁止写入仓库、日志、文档、Issue 或发布制品。
- 凭证通过环境变量、仓库外 `.env` 或应用支持的引用方式提供；API 响应不得回显明文 Key。
- 默认认证关闭。启用 `RAG_AUTH_ENABLED=1` 时，必须同时提供 `RAG_AUTH_API_KEY` 和长随机 `RAG_AUTH_JWT_SECRET`。
- JWT 默认有效期为 3600 秒，可用 `RAG_AUTH_JWT_TTL_SECONDS` 调整，最小 60 秒。
- 当前没有 Refresh Token、服务端撤销列表、账户体系或 MFA；密钥泄漏后必须替换 API Key 和 JWT secret，并重启服务使旧签名失效。

### 1.4 依赖与制品

- Python 声明依赖位于 `requirements.txt`、`requirements-dev.txt` 和 `requirements-docker.txt`；前端依赖位于根 `package.json` / lockfile；桌面壳依赖位于 `src-tauri/Cargo.toml` / lockfile。
- 当前 CI / 发布基线包含 `npm audit --audit-level=high` 与针对声明 requirements 的 `pip-audit`。执行结果必须按实际记录，不能把历史结果当作本次结果。
- Rust 依赖是否执行自动漏洞审计为 TBD；不能声称已有 `cargo audit` 门禁。
- v2.0.0 Windows NSIS 已发布但没有 Authenticode 签名；下载者应核对 Release 中记录的 SHA-256，哈希校验不等于发布者身份签名。
- 仓库没有 `LICENSE`，许可证状态仍为 `UNLICENSED / TBD`，详见 `license-selection.md`。

### 1.5 网络边界

- 直接运行 `app.py` 时保持默认 `127.0.0.1:8765`，不要改为公网监听后仍关闭认证。
- Docker `compose.yaml` 当前使用 `${KI_PORT:-8765}:8765`，未绑定特定宿主机 IP。启动后用 `docker compose port web 8765` 和主机防火墙检查实际暴露范围。
- 需要跨主机访问时，必须启用认证，并在受控反向代理或等效边界终止 TLS；仓库当前没有内置 TLS 配置。
- `/api/health` 和静态首页在认证启用后仍放行；健康接口只返回活性状态，不得暴露配置或凭证。

## 2. 认证与浏览器安全

| 项目 | 当前状态 |
|------|----------|
| 默认身份模型 | 本地单用户、认证关闭；访问本机端口的用户视为同一隐式角色 |
| 可选认证 | `X-API-Key` 或 Bearer JWT；不是多用户 / RBAC |
| JWT 有效期 | 默认 3600 秒，最小 60 秒 |
| Token 刷新 | N/A；未实现 Refresh Token |
| 服务端撤销 | N/A；未实现撤销列表 |
| MFA / 2FA | N/A；无账户体系 |
| TLS | N/A；应用未内置，跨主机部署需在外部受控边界提供 |
| 浏览器内容 | 文档和模型返回内容均视为不可信；Markdown / HTML 清洗边界不得放宽 |
| CSRF | 默认本机无 Cookie Session；若未来新增 Cookie 认证，必须重新评估 |
| CORS | 不应为方便调试放宽到不受信任来源；实际变更需同步 API 与安全测试 |

认证启用后的保护路径、放行路径和错误响应以 `../design/api-spec.md` 与 `../design/permission-matrix.md` 为准。

## 3. 数据分类

| 数据级别 | 项目内示例 | 访问 / 存储要求 | 传输要求 | 保留 / 删除要求 |
|----------|------------|-----------------|----------|-----------------|
| 公开 | 仓库中公开的源码、文档、公开 Issue | 可公开读取；写入仍受仓库权限控制 | GitHub HTTPS 等平台实际机制 | 按 Git 历史与仓库治理保留 |
| 内部 | 未公开开发记录、普通本地知识库内容、聊天与评估结果 | 限当前主机账号和获授权仓库成员；本地数据目录不得公开共享 | 默认仅本机；外发 Provider 前由数据 Owner 确认 | 当前无自动策略；由数据 Owner 决定 |
| 机密 / 受限 | API Key、JWT secret、含个人或商业机密的导入文档 | 禁止入库到公开仓库；使用主机权限和磁盘保护；凭证只从环境注入 | 只通过受信网络和已评估 Provider；不在明文日志传输 | 泄漏凭证立即轮换；文档保留与删除期限 TBD |
| 日志与诊断 | 终端输出、Docker logs、测试输出、脱敏错误 | 先脱敏再共享；当前没有集中日志平台 | 仅在排障所需范围传输 | 自动保留期限 TBD；排障后删除不必要副本 |

项目当前没有经过确认的个人信息、支付或受监管数据处理承诺。导入此类数据前，必须先完成适用性和处理规则确认。

## 7. 第三方依赖与集成

| 依赖 / 集成 | 类型 | 数据流向 | 权限 / 凭证 | 主要风险与退出方式 |
|-------------|------|----------|-------------|-------------------|
| DeepSeek 或其他 OpenAI-compatible LLM / Embedding API | 外部服务 | 查询、提示词、检索片段或待嵌入内容可能离开本机 | 用户提供的 Provider Key | 服务商数据政策、可用性和配额不由本项目控制；可改用已支持的其他 Provider 或本地模式 |
| Ollama | 可选本地服务 | 提示词与检索内容发送到配置的 Ollama 地址 | 默认不使用云端 Key | 地址若改为远程即改变信任边界；退出时切换 Provider |
| Qdrant local mode | 本地向量库 | 向量和关联标识写入本地目录 | 本机文件权限 | 目录损坏或与 SQLite 不一致；可退回 SQLite 向量模式并重建索引 |
| GitHub / GitHub Actions | 代码托管与 CI | 公开源码、PR、Issue、构建日志 | GitHub 账号与仓库权限 | 公开日志泄密、账号单点；使用最小权限、MFA，并保留本地 Git 副本 |
| Obsidian Bridge | 本地插件集成 | 项目上下文和生成内容在桌面应用与插件之间流转 | 本地连接认证 | 插件权限与 Vault 内容边界；不用时关闭连接或卸载插件 |

任何新增外部服务、遥测或远程存储在接入前都必须补充数据流、凭证、退出方案和用户告知。
