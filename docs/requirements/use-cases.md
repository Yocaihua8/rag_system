# 用例定义

> 状态：Active
> Owner：RAG 团队
> Last Updated：2026-08-01
> Scope：当前用户用例、前置条件和成功标准
> Related：`functional-modules.md`、`../features/README.md`、`../design/state-flow-and-acceptance.md`

## UC-01 创建项目并导入资料

- 前置条件：后端可访问；用户选择或创建一个项目。
- 主流程：用户选择受支持的来源，预览或提交导入，系统记录文档、分块和批次结果。
- 成功标准：成功与跳过项可区分；单文件失败不阻断其他文件；资料归属当前 `project_id`。
- 降级边界：URL 摘录弹窗参数目前不完整，不作为成功闭环；一次性 Vault 导入不等于插件连接。

## UC-02 围绕项目进行来源问答

- 前置条件：当前项目已有可检索资料。
- 主流程：用户在教练视图提问，系统混合检索来源，通过 SSE 输出回答并在完成时保存消息。
- 成功标准：`done` 结果与同步回答结构一致，来源可追溯；取消后关闭当前流。
- 降级边界：模型不可用时返回来源片段组合；无命中时明确缺少来源，不生成伪造引用。

## UC-03 分析项目并查看学习地图

- 前置条件：当前项目已有资料。
- 主流程：用户发起分析，系统生成概览、知识点、来源和技能映射；学习地图加载覆盖与历史评估。
- 成功标准：每项结论有真实来源；未评估与低分状态分别展示。
- 降级边界：来源变化后历史分析只读且标记 `stale`，重新分析前不能发起新评估。

## UC-04 完成定向评估

- 前置条件：存在当前有效分析和可选知识点或技能目标。
- 主流程：系统创建或恢复评估会话；用户逐题作答；服务端保存规则或模型评分结果。
- 成功标准：作答前不泄露评分要点；作答后返回状态、分数、置信度、证据、缺失点和来源。
- 降级边界：模型评估失败时可使用规则评估；结果不外推为整体职业能力。

## UC-05 生成并确认学习计划

- 前置条件：当前项目存在有效分析。
- 主流程：用户生成草稿、编辑或排序任务、确认计划，并更新确认版任务进度。
- 成功标准：结构更新和进度更新遵守服务端并发校验；确认后计划结构保持不可变；再次生成产生新修订。
- 降级边界：没有真实来源的内容只能形成 `source_gap`，不能伪造阅读材料。

## UC-06 连接 Obsidian 并同步来源

- 前置条件：本机后端和桌面 Obsidian 插件可访问；用户已创建配对码。
- 主流程：插件换取项目令牌，批量发送 Markdown 变更事件，并在离线恢复后幂等重放。
- 成功标准：事件按连接内 `event_id` 幂等；重命名保留来源身份；删除清理索引并使依赖分析过期。
- 降级边界：系统输出根中的文件不反向摄入；撤销连接后令牌不再可用。

## UC-07 受控发布到 Obsidian

- 前置条件：当前项目存在活动连接、有效分析和已确认学习计划。
- 主流程：用户预览内容和目标路径并确认；插件领取排队任务、检查文件后写入并回传结果。
- 成功标准：只有受管文件且 hash 基线一致时允许更新；最终状态来自插件回传。
- 降级边界：路径越界、管理标记缺失、外部修改或插件离线时不得宣称发布成功。

## UC-08 配置模型与诊断检索

- 前置条件：用户主动选择本地或外部模型方案。
- 主流程：用户保存并测试 LLM 设置或 Profile，调整项目检索参数，执行检索调试、复盘或只读 Agent 工具。
- 成功标准：接口不回显 API Key；工具只能来自只读白名单，运行记录可审计。
- 降级边界：当前 Vue 未装配后端可选认证凭证；认证开启时普通页面和问答 SSE 不属于已验证流程。

## 全局验收约束

- 普通界面使用“项目”或“工作区”，HTTP 与数据库使用 `project_id`。
- 当前可达、仅兼容保留、部分接线和未实现能力必须明确区分。
- 任何项目知识结论没有来源时必须省略或标记未知。
- 只有用户主动配置模型或启动受控网络导入时才访问外部服务。
- 默认运行只写 v2 数据根；不得隐式修改旧代际数据。
