## 1. 目的

本文件保留 B-156/B-159 已落地的 Codex 式工作区与中性视觉基线，并记录 B-160～B-164 已落地的 Knowledge Island 2.0 项目知识教练工作流。

当前主体验让普通用户只理解一条学习闭环：

```text
导入代码项目与笔记 -> 生成有来源的项目理解 -> 学习问答 -> 项目知识评估
-> 通用技能差距 -> 学习计划 -> 确认后发布到 Obsidian
```

页面继续遵守“内容优先、能力按需出现”的 Codex 式结构，不把资料管理、检索调试、模型配置、评估结果和导入审计铺成管理后台。

## 2. 设计结论

2.0 沿用三类核心区域：

| 区域 | 用户理解 | 主要职责 |
|------|----------|----------|
| 项目与导航侧栏 | 我在学习哪个项目、下一步去哪 | 当前项目、教练、学习地图、学习计划、资料、设置 |
| 任务主区 | 我现在要理解、评估或计划什么 | 按入口展示教练会话、项目知识地图或学习计划 |
| 依据抽屉 | 这个回答或结论参考了什么 | 展示回答来源、知识点来源、评估证据和只读工具结果 |

导航只保留必要入口：

| 入口 | 定位 | 是否在首页展开 |
|------|------|----------------|
| 教练 | 默认首页，围绕当前项目问答并提示下一步学习动作 | 是 |
| 学习地图 | 项目理解、知识覆盖、辅助技能差距和评估记录 | 否，进入专属主区 |
| 学习计划 | 编辑、排序、确认计划并发起 Obsidian 发布预览 | 否，进入专属主区 |
| 资料 | 添加和浏览当前项目资料，管理 Obsidian 真实连接状态 | 否，弹窗或覆盖层 |
| 设置 | 回答引擎、Obsidian 连接、资料保存、备份和外观 | 否，全屏页 |

评估不设置一级入口，从教练输入区工具菜单或学习地图节点打开覆盖层；关闭后必须返回原上下文。学习地图与学习计划也不得做成彩色统计大屏。

当前可交互 HTML 预览：

- `docs/previews/codex-anythingllm-workspace-preview/index.html`

## 3. 命名规则

普通界面使用用户能直接理解的词：

| 内部或技术词 | 普通界面文案 | 说明 |
|--------------|--------------|------|
| project / 项目空间 | 工作区 | 用户理解为一组资料和会话 |
| session / 线程 | 会话 | 目标普通文案；当前已实现界面中的“线程”保留到专门的前端文案同步任务 |
| import / ingest | 添加资料 | 不使用“摄入” |
| model / LLM | 回答引擎 | 具体模型名放设置详情 |
| source / retrieval hit | 参考资料 | 回答依据的普通说法 |
| assessment | 开始评估 / 评估结果 | 从教练或学习地图进入覆盖层；结论限定为当前项目 |
| knowledge coverage | 知识覆盖 | 主评价口径 |
| skill gap | 技能差距 | 辅助解释项目知识差距，不代表职业能力 |
| publication | 发布到 Obsidian | 必须先预览并由用户确认 |
| agent tool | 工具 | 只读能力，不暴露 Agent 概念 |

内部 API、数据库和代码可以继续使用 `project_id`、`session_id` 等现有命名。UI 文案变化不要求同步重命名底层字段。

术语边界：

- 当前用户界面已使用“工作区”；后端、API 和数据库继续使用 `project` / `project_id`。
- `项目空间` 是历史文档中的同一概念，阅读旧文档时应按“工作区”理解，不应据此新增另一种业务实体。
- “会话”是后续普通文案的目标；若修改现有“线程”文案，必须同步代码、功能规格与测试断言。

以下词不应出现在普通首页：

- RAG
- Agent
- Prompt
- Profile
- Chunk
- 向量
- top_k
- 检索调试
- Embedding
- Reranker

如确需展示，必须放入高级详情、设置页或调试入口。

## 4. 当前教练入口与 1.x 聊天兼容基线

### 4.1 首页只保留的信息

当前“教练”首页继续复用 1.x 聊天的克制结构，只展示当前会话和学习动作必须的信息：

- 当前工作区
- 会话列表
- 当前会话内容
- 输入框
- 添加资料入口
- 回答引擎入口
- 依据入口
- 当前项目分析状态与一个明确的下一步学习动作；不得在教练首页铺开整张学习地图或计划列表

首页不展示：

- 项目健康统计
- 导入批次历史
- 文件管理列表
- 检索调试
- 工具运行历史
- 模型详细参数
- Prompt 预设
- 评估结果
- 备份恢复
- 数据库或向量状态

### 4.2 左侧工作区侧栏

左侧侧栏参考 Codex 的工作方式：

```text
Knowledge Island
[当前工作区 v]                 [添加资料]

会话
[搜索会话]
[+ 新建会话]

- 默认会话
- 接口设计讨论
- 资料导入问题
- 前端重设计

[资料] [设置]
```

行为规则：

- 点击当前工作区打开工作区切换面板。
- 新建会话必须归属当前工作区。
- 切换工作区后，会话、资料、回答来源和工具记录都切换到该工作区。
- 会话文案统一使用“会话”，不在普通界面使用“线程”。
- 默认会话在前端显示为“默认会话”；请求现有 API 时继续不传 `session_id`，兼容历史消息。

第一版不设计会话置顶、归档、收藏、跨工作区移动和智能自动命名。这些能力需要后续接口支持。

### 4.3 中间会话主区

会话主区只承载聊天：

```text
[会话标题]                                      [查看依据]

用户：这个项目的导入流程应该怎么设计？

回答：可以分为选择工作区、选择资料来源、预检、导入、查看结果五步...
      [参考资料 3]

┌────────────────────────────────────────────┐
│ 输入问题...                                │
│ [+] [工具]                       [本机 v] [发送] │
└────────────────────────────────────────────┘
```

输入框左侧：

- `+`：添加资料、上传临时文件、练习一下、整理要点。
- 工具：快捷指令、自定义工具、后续 MCP 入口。

输入框右侧：

- 回答引擎：本机、快速、在线。
- 思考程度：轻、标准、深入。
- 发送。

如果后端暂不支持单次思考程度，前端只能把它作为未生效的本地选择或设置入口，禁止表现成已经影响本轮回答。

### 4.4 右侧依据抽屉

依据抽屉默认收起，只在用户点击回答来源、顶部依据按钮或来源不足提示时打开。

抽屉内容按优先级展示：

1. 本次回答参考了哪些资料。
2. 每条来源的片段预览。
3. 来源不足时的补充建议。
4. 用户手动运行的只读工具结果。
5. 高级详情。

高级详情可以包含命中数、模型模式、耗时等信息，但默认不展示分数、chunk、向量、top_k 等技术字段。

## 5. 资料导入设计

资料导入参考 AnythingLLM 的“来源卡片 + 分步导入”体验，但不做连接器市场。

入口统一叫“添加资料”。

### 5.1 标准流程

所有资料入口遵循五步：

| 步骤 | 页面动作 | 说明 |
|------|----------|------|
| 1 | 选择目标工作区 | 没有工作区时先创建；不能无工作区问答 |
| 2 | 选择资料来源 | 用来源卡片分组展示 |
| 3 | 填写内容或预检 | 能预检的调用后端预检，不能预检的不伪装 |
| 4 | 开始导入 | 按钮进入等待状态，显示“正在处理资料” |
| 5 | 查看结果 | 展示摘要、刷新资料列表，提供“开始提问” |

后端当前没有通用导入任务进度流，因此导入时禁止显示百分比进度或后台队列。可以显示等待状态和当前动作说明。

### 5.2 来源分组

资料来源按普通用户理解分组：

| 分组 | 来源 | 当前边界 |
|------|------|----------|
| 本机资料 | 绑定目录同步 | 只对项目绑定的后端可见目录有效 |
| 本机资料 | 选择本机文件夹上传 | 浏览器授权后上传内容，不代表后续持续同步 |
| 本机资料 | 选择文件上传 | 支持一个或多个文件 |
| 本机资料 | Obsidian | 使用现有导入能力时展示；不可伪装账号连接 |
| 手写资料 | 文本笔记 | 写入当前工作区资料 |
| 手写资料 | 剪贴板文本 | 复用文本笔记能力 |
| 手写资料 | URL 摘录 | 保存 URL、标题和手动粘贴正文，不自动抓网页 |
| 网络资料 | 单网页抓取 | 只支持用户手动触发的单个公开网页，先预览再确认 |
| 网络资料 | GitHub 仓库 | 只接收 GitHub clone URL，通过本机 git 拉取；不接 GitHub API，不保存 token |
| 迁移资料 | Notion ZIP | 作为离线导入，不是 Notion 账号连接 |

未实现或能力不完整的来源不得显示为“已连接”“同步中”或“导入成功”。

当前 Obsidian 能力分为两条明确路径：

1. **资料源**：桌面插件把 Markdown 的新增、修改、重命名、删除及 Frontmatter、标签、Wikilink 事件同步给当前项目；系统生成输出目录不反向摄入。
2. **成果出口**：学习计划或评估完成后，先预览内容和目标路径，再由用户确认发布项目理解、知识覆盖与技能差距、学习计划或评估记录。

每个项目最多一个活动连接。未连接、离线、令牌过期、已撤销、无系统标记、哈希变化或越界路径都必须显示真实状态并停止覆盖；v1 插件桥接不做自动合并。

### 5.3 导入结果

导入结果使用普通语言：

| 后端含义 | 普通文案 |
|----------|----------|
| created/imported | 已加入 |
| updated | 已更新 |
| unchanged | 已存在 |
| skipped | 已跳过 |
| error | 失败 |
| deleted | 已移除记录 |

展示结构：

1. 顶部摘要：已加入、已更新、已跳过、失败。
2. 明细分区：成功入库、普通跳过、读取失败。
3. 批次历史：默认折叠，只在资料管理中查看。

跳过不等于失败。格式不支持、超过大小限制、PDF 缺少解析器、扫描 PDF 无文本等应作为跳过或受控失败说明。

第一版禁止提供：

- 回滚批次。
- 重试批次。
- 删除批次。
- 精确导入进度。

### 5.4 已导入资料浏览

资料浏览属于资料区域，不进入首页主区。

资料区域支持：

- 当前工作区资料列表。
- 路径搜索。
- 集合过滤。
- 未分组过滤。
- 点击资料预览正文。
- 删除资料记录。
- 查看最近导入批次。

边界：

- 集合只影响资料列表过滤，不改变问答范围。
- 当前问答范围是当前工作区全库。
- 选择单个资料只能做预览或把文件名插入问题提示，不能表现成“本轮只问这个文件”。

## 6. 设置设计

设置使用全屏页面，不挤压聊天首页。

左侧为设置菜单，右侧一次只显示一个设置页：

| 设置页 | 内容 |
|--------|------|
| 回答引擎 | 本机、快速、在线回答选择 |
| 本机模型 | Ollama 状态、推荐模型、拉取入口 |
| 在线 API | OpenAI-compatible 地址、模型名、连接测试 |
| 访问密钥 | API Key 来源和状态，不回显明文 |
| 资料保存 | 当前保存位置、说明和后续迁移入口 |
| 备份恢复 | 导出和恢复当前工作区资料 |
| Obsidian | 当前项目连接状态、一次性配对码、输出目录、令牌撤销和最近同步；一次性只读导入保留在资料弹窗并使用不同文案 |
| 外观 | 深色模式、界面密度 |
| 高级 | 检索参数、Prompt、Profile、调试入口 |

技术字段默认收起，只有用户进入对应设置页后才展示。

## 7. 当前 Coach 评估与 1.x 兼容设计

练习或评估不作为一级入口。

入口位于教练输入框 `+` 或学习地图节点：

- 练习一下。
- 检查掌握情况。
- 根据当前资料出题。

交互表现为保持原页面上下文的覆盖层：

1. 用户点击“练习一下”。
2. 用户可选择知识点或技能节点，系统恢复或创建持久评估会话。
3. 用户在覆盖层回答；作答前不返回评分依据。
4. 系统展示当前项目状态、评估方式、置信度、命中证据、缺失点和来源。

B-164 已接入持久化 Coach 评估覆盖层，可从知识点或技能节点定向发起。提交后显示 `unassessed / needs_work / developing / mastered` 状态，并注明“这是当前项目中的评估结果，不代表整体职业能力”。旧 `AssessmentView` 与 `/api/assessment/*` 继续保留兼容，不进入一级导航。

普通文案使用：

- 已掌握。
- 基本理解。
- 还需要补充。
- 暂时没掌握。

不在普通界面使用“掌握度评估模块”。

## 8. 后端和接口边界

### 8.1 可直接复用的能力

当前 Vue 主体验复用现有 API：

- 工作区列表、创建、改名、删除。
- 会话列表、新建、改名、删除。
- 消息列表、流式问答、回答反馈。
- 文件夹导入、文件上传、笔记、URL 摘录、网页抓取、GitHub 仓库、Obsidian、Notion ZIP。
- 文档列表、文档预览、文档删除、集合过滤。
- 导入批次列表和详情。
- 只读工具运行和工具结果回填。
- 模型设置、模型 Profile、Prompt 预设。
- 评估题库、开始评估、提交答案。
- 备份导出和恢复。
- Coach 项目分析、理解、知识点、技能、定向评估、覆盖和学习计划。
- Obsidian 用户侧配对发起、连接查询/撤销以及发布预览/确认。

浏览器不持有插件令牌，也不调用配对完成、同步事件、待执行发布领取或结果回传接口；这些路由只供 Obsidian 桌面插件使用。

### 8.2 第一版禁止伪装的能力

以下能力需要后端新任务，前端第一版不能伪装：

- 跨工作区共享资料或全局资料库（B-157 已停止推进）。
- 跨工作区问答。
- 只选择几个文件作为本轮回答范围。
- 集合作为检索范围。
- 通用导入实时进度。
- 会话置顶、归档、收藏。
- 自动智能会话命名。
- 批次回滚或重试。
- GitHub 账号连接或持续同步。
- MCP 工具市场。
- 多用户团队空间。
- 未经预览和确认自动写回 Obsidian。
- 自动覆盖无系统标记、哈希变化或越界路径的 Obsidian 笔记。

## 9. 响应式和桌面壳

桌面端优先：

- 左侧工作区侧栏固定。
- 用户点击收起后，左侧侧栏必须完全隐藏，不保留品牌窄栏或空白占位；顶部菜单按钮用于重新打开。
- 中间会话主区自适应。
- 右侧依据抽屉默认收起。
- 设置页全屏覆盖。
- 添加资料可用弹窗或独立资料页，但不得挤压会话主区。

移动端或窄屏：

- 默认只显示会话主区。
- 工作区侧栏通过菜单抽屉打开。
- 依据抽屉从右侧或底部打开。
- 输入框按钮减少为图标，长文字进入菜单。

## 10. 交互动效规则

动效只用于说明界面状态变化，不用于装饰。第一版需要设计，但必须克制：

- 侧边栏展开和完全隐藏：160-220ms，横向滑动，隐藏后不保留品牌窄栏或空白占位。
- 依据抽屉打开和关闭：160-220ms，从右侧进入；窄屏可从右侧或底部进入。
- 添加资料弹窗打开：180-240ms，轻微淡入和缩放；关闭时不需要复杂动画。
- 资料导入步骤切换：120-180ms，内容轻微淡入，不做页面大幅移动。
- 设置页打开：180-240ms，全屏淡入或轻微上移进入，返回时直接回到原会话。
- 聊天输入框左下角 `+` 菜单、自定义工具菜单：100-150ms，轻微淡入。
- 加载状态只允许使用文字、静态提示或非常轻的呼吸效果；没有真实后端进度时，不显示进度条。

动效边界：

- 必须支持系统“减少动态效果”设置，命中时动画降到最短或关闭。
- 不使用循环背景动画、彩色流光、弹跳、旋转等装饰性效果。
- 不通过动画暗示后端尚未支持的能力，例如实时导入进度、批次回滚、跨工作区同步。
- 动画不得改变主要布局尺寸，避免会话区、输入框和资料面板跳动。

## 11. 视觉规则

视觉方向为黑白灰轻量界面：

- 背景：白色或浅灰。
- 文字：黑色和深灰。
- 选中态：浅灰背景。
- 主按钮：黑底白字。
- 边框：浅灰。
- 错误：少量红色。
- 警告：少量黄色。

禁止：

- 大面积彩色渐变。
- 管理后台式数据卡片堆叠。
- 首页铺满说明文案。
- 用专业术语做按钮名。
- 用不可用能力占据主流程。

图标应优先使用通俗符号：菜单、加号、文件夹、文件、链接、齿轮、发送、返回、搜索。

## 12. 当前实现与发布验收边界

B-164 当前实现遵守：

1. 应用默认进入教练首页。
2. 首页只显示当前工作区、会话、聊天输入和依据入口。
3. 当前界面仍保留“线程”历史文案；统一改为“会话”需要单独同步源码与测试。
4. 添加资料入口清楚可见。
5. 资料导入按五步流程运行。
6. 导入结果区分已加入、已更新、已跳过和失败。
7. 已导入资料可以浏览和预览。
8. 首页不展示检索调试、导入批次、工具历史和模型详细参数。
9. 回答依据默认收起，用户需要时打开。
10. 设置是全屏页，技术字段默认收起。
11. Coach 定向评估从教练 `+` 或学习地图节点进入，不作为一级页面；旧评估页只保留兼容。
12. 不伪装后端未支持的跨工作区资料、文件级问答范围、实时导入进度和批次回滚。
13. 侧边栏、资料弹窗、依据抽屉、设置页和菜单具备克制的状态切换动效，并支持减少动态效果。

14. 一级入口固定为 `教练 / 学习地图 / 学习计划 / 资料 / 设置`，评估不成为一级页面。
15. 项目理解、知识覆盖、技能差距、评估结果和计划阅读项均可打开真实来源。
16. 学习计划区分草稿与已确认版本：草稿可编辑排序，确认版只更新进度，重新生成不覆盖已确认计划。
17. Obsidian 一次性只读导入与插件连接使用不同状态文案；资料和设置只展示真实连接。
18. 发布前展示内容与目标路径并要求用户确认；确认后显示 `queued / 等待插件执行`，最终应用或冲突由插件回传。
