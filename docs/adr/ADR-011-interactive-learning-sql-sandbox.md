# ADR-011 逐知识点学习会话与只读 SQL 沙箱

> 状态：Accepted
> Date：2026-08-01
> Owner：RAG 团队
> Scope：Coach 逐知识点学习状态、attempt 证据与 SQL 练习执行边界
> Related：`../features/project-knowledge-coach.md`、`../design/api-spec.md`、`../design/database-design.md`、`../design/architecture-overview.md`、`../guides/security.md`、`../plans/B-171-interactive-knowledge-learning.md`

## 1. 背景

现有 Coach 定向评估以 `UNIQUE(session_id, question_id)` 保存单份答案，只支持 `active / completed / abandoned`，无法表达逐知识点讲解、多次 attempt、有限重试、答案揭示和证据资格。SQL 练习还必须执行用户查询；若连接正式数据库、执行来源 DDL 或依赖模型判断，将突破本地项目知识教练的数据与安全边界。

旧 `feature/b-168-interactive-knowledge-learning` 分支包含一套未合并实现，但其文档编号、测试目录和前端同源请求假设已经落后于当前主线。B-171 只把可验证的行为语义移植到当前架构，不把该分支或旧 ADR-010 整体合入。

## 2. 决策结论

采用独立的 `coach_learning_*` 增量模型承载学习会话、步骤、练习和 attempt，保留旧 Coach 评估表与接口不变。SQL 练习只在当前项目存在可解析 Schema 证据时生成，以结构化 fixture 创建每次独立的临时 SQLite 数据库，只执行受 authorizer、超时和结果限制保护的单条只读查询；确定性执行结果是唯一评分结论，模型只能补充反馈。

数据库增量边界、正式数据库零访问、旧接口兼容与双运行时前端请求已由 B-171 当前提交的隔离测试和完整本地门禁验证，因此接受本决策。PR 最终 SHA 与 main 合并提交的 hosted CI 仍是独立合并门禁，不由 ADR 状态代替。

## 3. 决策原因

1. 独立 attempt 模型可保留完整重试历史、幂等语义和来源版本证据，不破坏旧评估兼容性。
2. 结构化 fixture 与临时数据库使用户 SQL 无法获得正式 `runtime/v2/app.db` 路径或连接。
3. authorizer、进度处理器、资源上限和结果比较可提供可测试的确定性边界，不依赖提示词约束。
4. 掌握度继续动态投影，可保留旧历史并让过期证据自然失效，避免额外汇总表漂移。

## 4. 备选方案

### 4.1 扩展现有评估答案表

- 优点：表数量更少。
- 缺点：需要移除既有唯一约束并改变旧接口语义，迁移和兼容风险高。
- 未采用原因：违反旧评估记录只读可追溯和接口兼容要求。

### 4.2 在前端或题目 JSON 中保存重试和 SQL 状态

- 优点：后端改动较小。
- 缺点：刷新后丢失、无法并发保护、无法审计，也会把业务规则和评分依据暴露给前端。
- 未采用原因：不能形成可信掌握证据。

### 4.3 让模型判断 SQL 是否正确

- 优点：实现表面上更简单。
- 缺点：无法可靠验证等价查询、安全语义、`NULL`、重复行和排序要求。
- 未采用原因：模型不得推翻可确定性执行的答案。

## 5. 影响

### 5.1 正面影响

- 学习流程可恢复、可重试、可审计，并与当前项目来源版本绑定。
- SQL 正确性和安全限制可通过本地自动化测试完整验证。
- 旧 Coach 评估、学习计划和 legacy API 无破坏性迁移。

### 5.2 负面影响

- SQLite Schema 增加六张表，状态机、并发和恢复测试量显著增加。
- SQL Schema 解析只支持安全子集，部分项目即使使用数据库也不会生成 SQL 练习。
- 旧代码回滚后新表会保留为未使用数据，不自动删除。

### 5.3 对现有系统的改动点

- 新增六张 `coach_learning_*` 表及四个 Coach 学习会话 API。
- 新增学习会话领域服务、SQL fixture/评分模块和 Vue 覆盖层。
- 覆盖查询合并新 attempt，确认计划任务可由有效学习证据单调推进。
- 前端仍通过 `VITE_API_BASE_URL` 构造绝对 URL，FastAPI 仍不托管前端静态资源。
