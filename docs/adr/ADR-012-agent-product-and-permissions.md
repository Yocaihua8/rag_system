# ADR-012 v3 通用项目 Agent 与权限边界

> 状态：Accepted
> Partially Superseded by：ADR-017（仅取代 P2 先于 React 开工的时间门禁）
> Date：2026-08-02
> Owner：RAG 团队
> Scope：v3 产品定位、任务归属、工具能力和写操作确认
> Related：`../requirements/agent-product-v3.md`、`../design/agent-runtime-and-tool-contract.md`、`ADR-003-agent-readonly-whitelist.md`、`ADR-008-project-knowledge-coach-v2.md`

## 1. 背景

v2 以项目知识教练为产品主线，Agent 仅提供两个硬编码只读工具。v3 需要统一承载项目问答、分析、工作流、受控写入和产物，同时不能把本地 Agent 扩张为任意代码执行器。

## 2. 决策结论

Knowledge Island v3 定位为单用户、桌面优先、本地优先的通用项目 Agent：

- 产品只有一个 Agent 工作台，可管理多个项目和任务；任务创建后固定绑定一个项目。
- 读取和分析节点可自动执行；项目文件、外部系统、导出和发布等写动作必须请求用户确认。
- 工作流只能引用带类型、版本和权限声明的节点注册表，不提供任意 shell、脚本、HTTP、MCP 或路径节点。
- v2 教练能力进入 Project Insights，不再作为一级产品结构。
- v3 首版只支持手动触发，不提供计划任务、目录监听或无限自治。

本 ADR 取代 ADR-003 在 v3 目标架构中的“只允许两个只读工具”结论，并取代 ADR-008 的产品主定位；两份旧 ADR 仍保留 v2 历史和迁移前实现事实。

## 3. 决策原因

1. 一个任务线程可以统一呈现计划、证据、工具、审批、错误和产物，减少分散页面状态。
2. 类型化能力和审批快照能支持受控写操作，同时保留可审计和可恢复边界。
3. 项目固定归属可以阻止跨项目来源或写入泄漏。
4. 保留 Project Insights 能复用已验证的分析和学习能力，而不继续限制产品主线。

## 4. 备选方案

### 4.1 继续只做知识教练

- 优点：改动小，现有能力和 UI 可继续增量维护。
- 缺点：任务执行、工作流、审批和产物仍会散落为独立功能。
- 未采用原因：不能满足已确认的通用项目 Agent 方向。

### 4.2 提供任意编码 Agent

- 优点：能力最灵活，可执行用户自定义命令。
- 缺点：本地文件、凭证、网络和进程风险无法由当前产品边界可靠控制。
- 未采用原因：超出本地知识/项目 Agent 的安全目标。

## 5. 影响

### 5.1 正面影响

- 产品导航、领域模型和权限语言统一。
- 写操作能够在冻结参数下被明确批准和审计。

### 5.2 负面影响

- 需要新的任务、运行、工作流、审批和产物数据模型。
- 旧 Vue 信息架构不能渐进扩展为目标形态，需要独立前端替换。

### 5.3 对现有系统的改动点

- 新建 `/api/v3` 和持久执行器。
- v2 教练、学习地图和学习计划迁入 Project Insights。
- 现有只读工具逐步映射为节点注册表能力。

### 6.2 回滚策略

| 项目 | 内容 |
|------|------|
| 回滚触发条件 | v3 安全、恢复或核心任务验收不通过 |
| 回滚步骤 | 保持 v2 API、Vue 和 Tauri 入口不切换；撤回未发布的 v3 路由与配置 |
| 数据回滚说明 | v3 使用独立数据根，不修改或导入 v2 数据 |
| 回滚责任人 | RAG 团队 |
| 不可回滚的点 | 用户明确导出到项目或外部系统的产物不能由数据库回滚撤销 |

### 6.3 验证方式

- 每个写节点都产生审批且参数变化会创建新审批。
- 越权路径、未注册节点和任意命令配置被拒绝。
- 任务、来源、运行和产物始终固定在同一项目。
