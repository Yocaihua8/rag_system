## 5. 主闭环与插件验证

`tests/test_webapp/test_v2_coach_end_to_end.py` 使用隔离数据库完成：

```text
创建项目 -> 目录导入 -> 项目分析
-> 同步问答 + SSE 流式问答
-> 知识点定向评估 -> 覆盖率
-> 生成、编辑、排序并确认学习计划
-> Obsidian 配对 -> 四类产物预览
-> 用户确认 queued -> 插件 pending -> applied 结果回传
```

该测试同时确认：

- 作答前题目不返回 `expected_points`，结果记录 `rule`、置信度、证据、缺失点和来源 ID。
- 学习计划更新携带 revision / items hash，确认使用更新后的 hash。
- 发布预览包含 `project_understanding / knowledge_coverage / learning_plan / assessment_record`，每项都有管理 Frontmatter。
- 用户确认只进入 `queued`；插件领取与结果回传后才进入 `applied`。

Playwright 另在真实 Vue 页面完成项目创建、文本笔记导入、SSE 问答和回答依据展示，并通过测试专用全局 teardown 正常关闭 Uvicorn，不残留 18765 端口监听。

Obsidian 插件测试覆盖 Vault 事件元数据、输出目录过滤、离线队列、幂等重放、Frontmatter/身份/hash 校验、路径边界、串行原子写入和冲突不覆盖。

## 9. 残余风险与非目标

- 首版 Obsidian 插件遇到外部编辑、无标记文件或身份/hash 冲突时停止覆盖，不做自动合并。
- 插件仅支持桌面端，不包含移动端或社区市场发布。
- 当前是单机单用户、单项目评价；不提供团队空间、云同步、跨项目能力汇总、JD 或职业能力评价。
- 不提供旧数据库迁移；用户必须重新导入项目。
- 规则基线保证无 LLM 可用；模型增强仍取决于用户本机模型或 API 配置。
- Windows 原生 installer 仍需在补齐 MSVC/Windows SDK 后重新验证。

## 10. 最终判定

Knowledge Island `v2.0.0` 在当前本地功能分支上达到**源码与自动化发布候选就绪**。正式发布仍需按 `docs/guides/release-process.md` 补齐远端 CI、目标平台产物（若本次交付需要）、Tag、推送、合并和 Release；在这些动作完成前，不得对外宣称 `v2.0.0` 已正式发布。
