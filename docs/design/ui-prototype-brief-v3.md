# v3 Agent UI 原型简报

> 状态：Active
> Owner：RAG 团队
> Last Updated：2026-08-02
> Scope：面向首次使用者的 P1/P2 原型覆盖、布局、状态、防呆和前端实施门禁
> Related：`../requirements/agent-product-v3.md`、`../features/agent-tasks-and-runs.md`、`page-module-contract.md`

## 1. 原型门禁

前端原计划采用两轮可交互原型；用户对 Revision 3 的最新实施授权按 ADR-017 调整了第二轮的交付形态：

| 轮次 | 目的 | 必须确认的内容 | 对生产代码的影响 |
|------|------|----------------|------------------|
| P1 | 信息架构与核心交互 | 导航、页面层级、任务/审批流程、状态覆盖、响应式面板 | Revision 3 已获明确实施批准，作为 React 实施基线 |
| 高保真验收 | React 实现中的视觉与交互验收 | 组件、密度、颜色、文案、主题、键盘和完整异常状态 | 并入 React 实现；通过前不进入完整联调或最终切换 |

P1 原型使用明确标注的演示内容且不调用真实 API；第二阶段已按 ADR-017 改为消费真实 `/api/v3` 的 React 高保真实现。P1 内容不得作为正式应用的回退数据。

当前状态必须分层说明：

- 已交付的 P1 横屏版本未通过评审，不能作为 P1 批准依据。
- P1 Revision 2 的引导式任务首页已完成本地浏览器验收，但设置页作用域和“常用做法”命名未通过追加评审，不能作为 P1 批准依据。
- P1 Revision 3 已恢复“工作流”标准名称、区分应用设置与当前任务选项，并按常规桌面产品信息架构重做设置页；用户已于 2026-08-02 明确批准按该版本实施，可以创建独立 React 前端。
- 原 P2 的主题、视觉 token、键盘、响应式和完整异常状态要求并入 React 高保真实现验收；这次授权不等于完整联调或最终切换批准。
- v3 后端 alpha 已可持久执行固定四步项目检查与分段回答，但通用自然语言澄清仍只在 P1 中演示。
- 当前 React 实现只开放真实可用的项目结构检查；项目页限列表、创建和概况，工作流保持只读，设置仅保存本机主题与默认处理方式。资料、洞察、导出、工作流编辑/绑定和桌面数据运维继续明确禁用。

## 2. 目标用户与渐进披露

- 默认按首次使用者、低数字素养用户设计，使用尊重且直接的普通中文，不在界面标注用户能力或教育程度。
- 首屏一次只要求完成一个决定，最多提供 2–3 个选项，并提供“我不确定，按推荐处理”。快捷引导最多两轮。
- 默认使用“普通处理（推荐）”。处理深度和模型覆盖进入“任务选项”；Run ID、hash、工作流版本和技术日志进入“详细过程”。
- “任务选项”只影响尚未启动的当前任务，并与一级导航“设置”中的应用默认值明确分开；任务建立后固定所属项目，不能在执行中误切项目。
- 主要按钮使用动作词，正文不低于 16px，可点击区域至少 44×44px。状态必须同时用文字、图标和颜色表达。

## 3. 桌面布局

```text
┌──────────┬──────────────────┬──────────────────────────────────────────────┐
│ 主导航   │ 项目/任务历史    │ 对话主区                                     │
│ 80px     │ 256px            │ 时间线独立滚动，输入固定在底部               │
└──────────┴──────────────────┴──────────────────────────────────────────────┘
                                           详细过程：360px 右侧按需抽屉
```

- `>= 1280px`：显示主导航、项目/任务历史和对话主区；“详细过程”默认收起，打开后覆盖或压缩主区但不遮挡输入。
- `< 1280px`：项目/任务历史与详细过程均改为抽屉；同一时间最多打开一个辅助抽屉。
- `320px`：顶部导航、单列主区和全宽底部输入；全部主要动作可达且不横向滚动。
- 在 560px 视口高度下，输入、当前状态和唯一主操作仍可见；历史时间线在独立区域滚动。
- 自动选择最后使用的项目；没有项目时先显示一步式项目选择。草稿按任务隔离并自动保留，切换任务不得串稿。

## 4. 首页主流程与状态投影

首页空态只显示自然语言输入和“找出问题”“整理资料”“做一份计划”三个大入口。发送后必须按事实推进：

1. 本地请求提交时显示“正在发送”，禁用重复点击；只有服务端接受后才显示“已收到，正在准备”。
2. 顶部三段进度固定为“理解需求 → 正在处理 → 等你确认/已完成”，并显示真实步骤数量，不虚构百分比或预计时间。
3. 主区任意时刻只展开一个当前状态、一个运行步骤和一个主要操作；已完成步骤折叠到“查看处理过程”。
4. Agent 回答在同一气泡内按句子或段落增长。用户停留底部时自动跟随；用户主动上滚后停止抢滚动，并显示“有新进展”。
5. 完成时只突出“查看结果”，再给出一个推荐下一步；其他动作放进“更多”。

状态优先级为：需要恢复 > 等待确认 > 正在处理 > 新任务空态。暂停、失败、离线、取消和完成互斥显示，不能把不同演示分支同时堆在同一时间线上。最终业务状态只由服务端事件推进；P1 使用确定性演示事件模拟这一规则。

## 5. 风险分级与离线安全

- 只读分析直接执行。
- 可撤销写操作先展示一次影响确认；只有后端明确返回有效撤销能力时，成功后才提供 10 秒撤销。
- 不可逆或结果不确定的写操作必须经过“影响预览 → 最终确认”两步，不要求用户输入技术短语。
- 确认卡固定说明“将做什么、影响哪里、不会修改什么、能否撤销”，并把安全选项标为推荐；危险按钮不得默认获得焦点。
- “取消任务”改为“停止未完成步骤”，确认页优先提供“先暂停（推荐）”。命令提交中禁用重复操作，失败时恢复可操作状态而不伪造终态。
- 离线时保留已加载内容和本地草稿，但禁止启动、审批和写入；恢复连接后不自动补交。
- 错误固定说明“发生了什么、数据是否安全、下一步怎么做”，技术详情折叠。读取/分析重试显示当前次数，不确定写操作不自动重试。

## 6. 页面覆盖

### Tasks

- 任务列表：新建任务、项目绑定、搜索、状态和最近活动。
- 任务线程：用户消息、单一当前状态、分段回答、确认、错误和生成结果统一时间线。
- 固定输入区：自然语言、三个新手快捷动作和当前任务“任务选项”。
- 详细过程：处理计划、参考资料、生成结果和执行记录；默认不打断主流程。

### Project

- Sources/Connectors：本地来源、URL 预览确认、GitHub、Obsidian 和导入结果。
- Project Insights：Overview、Knowledge、Assessments、Learning Plan。
- 项目问答始终面向整个项目；资料选择只浏览和预览。

### Workflows

- 一级导航和页面标题固定使用“工作流”，辅助说明为“把重复任务保存为可复用步骤”；“常用工作流”可以作为页面内的模板分组，不能替代领域名称。
- 默认显示中文步骤列表；“编辑流程图”中提供类型化节点目录、DAG 画布、节点配置、校验结果、发布版本和项目绑定。
- 明确展示循环、孤立节点、类型不匹配、缺失参数和写节点缺少审批等错误。

### Settings

- 设置页使用稳定二级导航，而不是把主题、模型连接和存储迁移平铺成同权重动作卡：`通用` 管理外观与启动偏好，`模型` 管理 Profile、默认模型和连接测试，`集成` 管理外部服务及权限，`数据与存储` 管理数据位置、备份、恢复与迁移，`高级` 管理日志和技术详情。
- 低风险偏好采用明确控件并自动保存，显示“已自动保存”；模型凭据和连接配置在校验后显式保存；存储迁移与恢复必须进入“选择 → 自动检查 → 影响预览 → 最终确认”的独立向导。
- 应用设置不得修改隐藏的当前任务；当前任务覆盖项只从“任务选项”进入。离线时允许修改本地外观等偏好，但连接测试、审批和数据写入必须禁用并说明原因。
- 密钥只显示“已配置/未配置”和引用，不回显明文。危险操作与普通偏好分区展示，不获得默认焦点。

## 7. 必须覆盖的状态

- 页面：空、加载、部分加载、错误、离线和恢复连接。
- 运行：排队、运行、等待审批、暂停、失败、恢复、完成和取消。
- 步骤：重试、跳过、取消、`recovery_required`。
- 审批：待处理、已批准、已拒绝、已过期。
- 产物：草稿、可预览、导出中、已导出和失败。
- 项目：未选择、无资料、导入预检、部分失败、分析过期。
- 工作流：草稿、无效、有效未发布、已发布和新修订。

## 8. 文案与视觉原则

- 克制、工具化、低理解成本，不复制 AnythingLLM、Codex 或其他产品的品牌视觉。
- 中性表面配单一主强调色，弱阴影，清晰层级；亮色、暗色和跟随系统使用同一语义 token。
- 审批、失败和危险写操作必须同时使用文字、图标和位置表达，不能只靠颜色。
- 使用语义按钮、输入和可访问标签；键盘顺序与视觉顺序一致。

| 技术名称 | 默认界面文案 |
|----------|--------------|
| Workflows | 工作流 |
| Inspector | 详细过程 |
| Sources | 参考资料 |
| Artifacts | 生成结果 |
| Run | 执行记录 |
| Standard | 普通处理（推荐） |

- [x] “设置”与“任务选项”作用域清楚；设置页五个分区可达，普通偏好、连接配置和高风险数据操作采用不同保存与确认方式。
