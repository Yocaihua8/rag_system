# Agent 任务、运行与产物

> 状态：Proposed
> Owner：RAG 团队
> Last Updated：2026-08-02
> Scope：v3 任务线程、持久消息、分段回答、运行、审批、恢复和产物的目标行为
> Related：`../requirements/agent-product-v3.md`、`../design/agent-runtime-and-tool-contract.md`、`../design/ui-prototype-brief-v3.md`

## 1. 用户能力

用户可以在指定项目中创建任务、通过自然语言补充目标、启动一次运行，并在统一时间线查看消息、当前步骤、确认、错误和生成结果。任务可以有多次运行，但不能在创建后切换项目。

默认体验面向首次使用者和低数字素养用户：一次只要求一个决定，使用普通中文和推荐默认值。当前任务的处理深度、模型覆盖和双模型比较通过“任务选项”设置；工作流版本、Run ID 和详细日志通过“详细过程”查看。全局模型 Profile、集成、主题和存储归一级“设置”，不得借任务入口修改。

## 2. 任务、消息与输入快照

- 创建任务时，Task 与首条用户消息必须在同一事务持久化；任一写入失败都不得留下半个任务。
- 幂等回放必须返回同一 Task 和同一首消息，不得生成重复会话。
- 启动 Run 时必须引用该 Task 的 `input_message_id`。服务端校验归属后冻结消息引用和内容哈希，后续编辑或新消息不能改变已经启动的运行输入。
- 已完成 Agent 回答以完整任务消息作为长期会话事实；回答生成过程由只追加事件表达。中断时保留明确标记的可见部分和中断原因，不能伪装成完整回答。
- 新页面以任务消息加载已完成历史，以事件恢复正在生成的回答。React 实现已把草稿绑定到项目与真实 Task ID，并通过独立 v3 API 恢复服务端运行事实；不得复制原型演示数据。
- React 的未决操作 ledger 只保留 SHA-256 摘要、幂等键、阶段和消息 ID；Run 明确成功后释放记录，使用户可以再次提交相同正文形成新的运行。项目路径和原始 prompt 不进入 ledger。

## 3. 状态、进度与动作

任务和运行支持 `queued / running / waiting_approval / paused / completed / failed / cancelled`；运行恢复期间可为 `recovering`。用户只可执行服务端返回的动作：暂停、恢复、取消、重试、处理审批、预览或导出产物。

写步骤一旦开始后不得自动重放。应用重启后无法证明写结果的步骤进入 `recovery_required`，必须由用户检查后决定重试、跳过或取消。

失败 Run 的手动重试会创建新的直接后继 Run。同一失败源最多创建一个直接后继：首次成功命令的 `Idempotency-Key` 可安全回放，其他 Key 不会再创建重复运行，而是返回状态冲突；新的 retry Run 若之后失败，可作为新的失败源继续形成下一段重试链。

默认界面使用“理解需求 → 正在处理 → 等你确认/已完成”三段进度，并显示真实步骤数量，不从状态推测百分比或预计时间。任意时刻只能有一个当前运行状态和一个主要动作；按钮提交只能显示“处理中”，最终业务状态必须由服务端事件确认。

## 4. 分段回答与事件恢复

- 回答依次产生 `assistant.message.started`、一个或多个 `assistant.message.delta`、以及 `assistant.message.completed` 或 `assistant.message.interrupted`。
- delta 按句子或短段合并，使用稳定 `message_id` 和递增 `chunk_index`。客户端按 Run sequence 去重，不大于已消费 sequence 的事件不得再次追加。
- SSE 断开不取消 Run。重连使用 `Last-Event-ID` 或 `after_sequence` 继续；刷新后不得重复文字，也不得因为缺少当前连接而把运行显示为失败。
- 用户停留在时间线底部时可跟随新段落；用户主动上滚后停止抢滚动，并用“有新进展”返回最新内容。
- 完成时保存完整消息并追加完成事件；失败、暂停或取消不能发出伪完成事件或错误产物。

完整持久消息、只追加事件和前端 reducer 的职责见 [`ADR-016`](../adr/ADR-016-agent-message-stream.md)。

## 5. 审批与防误操作

- 读取与分析节点默认不请求批准。
- 项目文件、外部系统、发布和导出等写动作必须创建审批。
- 默认确认卡用普通中文说明“将做什么、影响哪里、不会修改什么、能否撤销”；请求哈希等技术信息进入详细过程。
- 批准只对当前审批快照生效；参数变化必须创建新审批。
- 拒绝、过期或取消结果进入时间线和审计事件。
- 只读分析直接执行；可撤销写操作一次确认，且仅在服务端明确提供撤销能力时显示 10 秒撤销。
- 不可逆或结果不确定的写操作必须经过影响预览和最终确认两步；危险按钮不得默认获得焦点。
- “停止未完成步骤”优先建议先暂停。审批、暂停、恢复、停止或重试提交期间禁用重复点击，失败后恢复安全可操作状态。

## 6. 产物

产物状态为 `draft / ready / exported / failed`。产物首先保存在应用受控存储中；导出到用户路径或外部集成是独立写动作，必须经过审批和路径校验。

完成状态默认只突出“查看结果”和一个推荐下一步。只有具备可验证数据时才展示项目结构、处理清单或文件影响图，不生成没有依据的健康分数。

## 7. 降级与错误

- 服务离线时保留已加载时间线并显示离线状态，不把网络失败显示为空任务。
- SSE 断开后按事件序号续传，不能重复显示已消费事件。
- 读取/分析步骤最多自动重试两次；持续失败后保留具体错误和可重试动作。
- 等待审批、暂停或恢复中的运行不得显示为完成。
- 离线时允许保留已加载内容和本地草稿，但禁止启动、审批和写入；恢复连接后不得自动补交。
- 错误必须说明发生了什么、数据是否安全和下一步怎么做；技术详情默认折叠。
