> Owner：RAG 团队

> Scope：Knowledge Island v3 的目标产品、角色、主流程与非目标

## 1. 产品定位

Knowledge Island v3 的目标形态是桌面优先、本地优先的通用项目 Agent。产品只有一个 Agent 工作台，可以管理多个项目和多个任务；每个任务创建时固定绑定一个项目，执行、来源、审批和产物都不能跨越该项目边界。

v2 知识教练能力不会消失，而是降为 Project Insights 下的项目分析、知识覆盖、评估和学习计划能力，不再占据一级导航。

## 2. 核心用户任务

```text
选择或创建项目
  -> 创建任务并描述目标
  -> Agent 形成计划并执行类型化步骤
  -> 读取/分析自动继续，写操作请求用户确认
  -> 时间线持续呈现证据、工具、状态和错误
  -> 生成可预览、导出或受控发布的产物
```

一级导航固定为：

1. `Tasks`：任务列表、任务线程、运行和产物。
2. `Project`：项目资料、连接器和 Project Insights。
3. `Workflows`：可视化工作流草稿、校验、发布和项目绑定。
4. `Settings`：模型、集成、主题、存储、备份和恢复。

## 3. 产品原则

- **后端权威**：任务、运行、步骤、审批、产物和能力标志均由后端返回，前端不复制业务状态机。
- **来源可追溯**：项目分析、回答和产物保留项目来源引用；没有证据时明确未知。
- **写操作确认**：读取和分析可以自动执行；项目文件、外部系统和产物导出/发布必须经过冻结参数的确认。
- **可恢复执行**：排队、暂停、取消、重试和重启恢复是正式产品能力，不依赖浏览器进程存活。
- **本地安全边界**：默认只访问用户显式绑定的项目和连接器，不开放任意 shell、脚本、HTTP、MCP 或任意路径。
- **人工触发优先**：v3 首版只支持手动启动任务和工作流，不提供定时任务或文件监听器。

## 4. 固定交互规则

- 项目问答默认检索整个当前项目；资料选择只用于浏览、预览和来源检查。
- 深度档位为 `Quick / Standard / Deep`，最多分别执行 4/8/16 个步骤与 1/3/6 轮检索。
- Compare 必须选择且只选择两个模型 Profile。
- 审批卡直接出现在任务时间线，展示动作、目标、冻结参数、风险和拒绝/批准结果。
- 工作流只允许注册表中的类型化节点，发布版本不可变；编辑已发布工作流时复制新草稿。
- 主题支持亮色、暗色和跟随系统，并保存在本地用户设置中。

## 5. 运行范围

- Desktop：Tauri 启动本地 FastAPI sidecar，使用环回随机端口和单次启动令牌。
- Web/API：复用同一 FastAPI 应用，但采用独立认证边界；不能复用桌面令牌。
- 数据：v3 默认使用 `runtime/v3/app.db`，不自动导入或覆盖 v2 数据。
- 并发：全局最多两个读取/分析运行槽；同项目写步骤串行；等待审批不占运行槽。

## 6. 非目标

- 多租户 SaaS、团队成员、RBAC、云端控制平面或默认公网部署。
- 任意代码执行、终端、脚本节点、任意网络请求或未授权项目路径。
- 无确认的文件写入、外部发布、Obsidian 修改或冲突覆盖。
- 定时器、目录监听、自动触发器和后台无限自治。
- 把学习覆盖解释为职业等级、招聘评价或跨项目个人排名。
- 在 v3 首版保留 `/api/v2` 兼容层或自动迁移旧代际数据库。

## 7. 交付状态边界

本文件是已批准的 v3 目标规格，不表示当前 v2 界面已经实现这些能力。当前可达行为仍以现有源码和 v2 功能文档为准；每个 v3 阶段只有在代码、测试、设计文档和 CHANGELOG 同步后才可标记为已实现。
