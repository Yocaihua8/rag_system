用于统一项目的安全要求、合规约束、事件响应路径。先落实通用基线，再根据项目是否联网、是否认证、是否存储数据和是否处理敏感信息启用条件项。

## 1. 通用安全基线

以下基线适用于所有项目；没有对应能力时标记 N/A，不因模板存在而虚构系统能力。

### 1.1 威胁与边界

- [ ] 识别需要保护的代码、数据、凭证、制品和运行资源
- [ ] 标明可信边界、不可信输入、外部依赖及主要失败后果
- [ ] 外部输入、文件和不可信数据进入核心逻辑前完成与风险相称的校验
- [ ] 账号、服务和自动化只获得完成任务所需的最小权限

### 1.2 数据

- [ ] 按项目实际数据分类确定采集、访问、存储、传输、备份和删除要求
- [ ] 只收集与当前功能直接相关的数据，并明确保留期限或删除条件
- [ ] 日志、错误信息、测试夹具和示例不包含真实凭证或不必要的敏感数据

### 1.3 凭证

- [ ] 密钥、Token、密码和私钥禁止写入仓库、日志或公开制品
- [ ] 凭证通过项目实际支持的环境注入或密钥管理方式提供
- [ ] 明确凭证的 Owner、权限范围、轮换方式和泄漏后的撤销路径

### 1.4 依赖

- [ ] 维护直接依赖、关键间接依赖和外部服务清单
- [ ] 使用项目现有且可运行的工具检查已知风险；没有对应工具时采用人工清单并将自动化能力标记为 TBD
- [ ] 升级依赖前评估兼容性、来源可信度、许可证和回滚方式

### 1.5 事件准备

- [ ] 明确私密上报渠道、安全负责人、证据保留位置和升级路径
- [ ] 安全响应目标使用本文件 § 6 的 token 或明确写为 TBD，不在模板中假设固定 SLA

## 2. 条件安全要求

| 启用条件 | 适用要求 |
|----------|----------|
| 项目自行处理认证凭证 | 使用经过评审的密码哈希或凭证方案，定义失效、轮换、撤销和审计边界 |
| 服务暴露在不可信网络 | 根据威胁模型采用受支持的传输保护，并明确终止位置、证书或等效信任机制 |
| 存在认证 / 鉴权 | 定义身份、权限、会话或 Token 生命周期以及必要审计事件；若启用 `../design/api-spec.md` 或 `../design/permission-matrix.md`，再同步对应契约 |
| 使用数据库或原生查询 | 使用安全的参数绑定或等效机制，并限制数据访问账号权限 |
| 向浏览器渲染不可信内容 | 按实际技术栈评估输出编码、XSS、CSRF、CORS 和内容安全边界 |
| 处理个人、支付或其他受监管数据 | 先确认适用法律、合同和行业要求，再定义最小化、加密、保留、删除和第三方处理规则 |
| 存在生产或长期运行环境 | 按实际部署方式定义调试信息、监控、备份、恢复和紧急变更边界 |

## 5. 安全验证清单

- [ ] 已通过项目实际支持的方式确认仓库和制品不含硬编码凭证；无自动工具时记录人工检查范围
- [ ] 已使用现有依赖管理工具检查依赖风险，或将缺失工具和后续动作标记为 TBD
- [ ] 已按威胁边界检查所有外部输入
- [ ] 数据库、浏览器、网络服务、认证和生产环境相关检查仅在对应能力存在时执行，否则标记 N/A
- [ ] 日志和错误信息不泄漏凭证、真实敏感数据或不必要的内部细节
- [ ] 已记录实际执行的命令、人工步骤、结果和未覆盖范围，不把不存在的工具写成强制命令
