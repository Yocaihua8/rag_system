## 0. 实现状态与 2.0 目标

| 范围 | 状态 | 说明 |
|------|------|------|
| `聊 / 库 / 设`、会话主区、依据抽屉、资料弹窗、评估工具和全屏设置 | 当前 1.x 已实现 | 以下“当前 1.x”章节记录现状，不因 2.0 设计立即改变 |
| `教练 / 学习地图 / 学习计划 / 资料 / 设置` | 2.0 目标，尚未成为当前导航 | 这是 2.0 冻结的信息架构，实施必须沿用 Codex 中性视觉 |
| Obsidian Vault 路径导入 | 当前 1.x 已实现 | 一次性只读导入，不是连接、持续同步或写回 |
| Obsidian 插件连接与成果发布 | 2.0 目标 | 资料源与用户确认后的成果出口；发生冲突时停止覆盖 |
| B-157 全局资料库 / 跨工作区共享 | 不再推进 | 不作为 2.0 页面或数据前置条件 |

2.0 桌面布局：

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ [项目与主导航侧栏]       │ [当前入口主区]                    │ [依据抽屉]     │
│ 当前项目                 │ 教练：会话与下一步学习动作        │ 回答来源       │
│ 教练                     │ 学习地图：项目理解与知识覆盖      │ 知识点来源     │
│ 学习地图                 │ 学习计划：可编辑任务列表          │ 评估证据       │
│ 学习计划                 │                                  │ 默认收起       │
│ 资料                     │ [评估覆盖层 / 发布预览，按需打开] │                │
│ 设置                     │                                  │                │
└──────────────────────────────────────────────────────────────────────────────┘
```

2.0 交互契约：

- **教练**是默认入口，复用当前聊天、流式回答与依据抽屉；资料管理和高级工具不铺满主区。
- **学习地图**展示项目理解、知识覆盖、辅助技能差距和评估记录。所有结论必须可查看来源，并注明“仅代表当前项目中的评估结果”。
- **学习计划**展示可编辑、可排序的草稿或已确认任务；重新生成不得覆盖已确认计划。
- **资料**继续使用弹窗或覆盖层，Obsidian 在此显示真实的一次性导入或插件连接状态。
- **设置**集中管理回答引擎、Obsidian 连接、输出目录、令牌撤销和高级能力。
- **评估**不是一级入口，从教练工具菜单或学习地图节点打开覆盖层；关闭后返回原上下文。
- **Obsidian 发布**必须先展示内容、目标路径和冲突，再由用户确认；目标输出包括项目理解、知识覆盖与技能差距、学习计划和评估记录。

## 1. 当前 1.x 页面清单

| 入口 | 目标用户 | 主要目标 | 优先级 |
|------|----------|----------|--------|
| 聊（默认首页） | 所有用户 | 围绕当前工作区资料聊天、整理、查看回答依据 | P0 |
| 库（弹窗） | 所有用户 | 加入资料、查看加入结果、选择已有资料 | P0 |
| 设（全屏页） | 所有用户 | 管理回答方式、在线连接、资料位置、备份恢复和外观 | P1 |

独立一级 `评估/练习` 入口已取消。当前 1.x 的练习与小测作为聊天输入框左下角 `+` 菜单中的工具进入；2.0 继续保持非一级入口，并升级为可从教练或学习地图进入的评估覆盖层。

## 2. 布局表达约定

```text
┌─────────────────────────────┐
│  [区域名称]  表示 UI 功能区  │  ← 方括号为区域标签，非代码
└─────────────────────────────┘
```

Vue 主体验采用左侧工作区和线程侧栏，页面通过 `聊 / 库 / 设` 主入口切换主流程。B-156 后，`库` 不切换普通页面，而是打开资料管理弹窗；`设` 是全屏覆盖页。B-142 工作台目标结构参考 AnythingLLM 的工作区模式，但只吸收信息架构：左侧工作区/线程，中间对话，右侧依据；不复刻多用户、Agent 写操作、Agent Flow 或模型路由。

页面主色采用黑白灰中性方案；错误和警告状态保留必要提示色。深色模式入口位于 `设 -> 外观`。

视觉令牌、组件状态、动效和无障碍要求统一见 `codex-ui-visual-system.md`。本文件只定义页面结构与交互，不重复维护样式细节。

## 3. 当前 1.x：聊（主页）

**页面目标**：支持多轮对话式 RAG 问答，查看来源和工具结果。

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ [左侧侧栏]                │ [中间聊天区]                    │ [依据抽屉]     │
│ Knowledge Island          │ ┌──────────────────────────────┐ │ 默认收起       │
│ 聊 / 库 / 设              │ │ [用户消息]  消息内容          │ │ 回答来源       │
│                            │ │ [AI 回答]  流式 Markdown      │ │ 来源质量       │
│ 工作区                    │ │ [反馈按钮] 有用 / 来源不准    │ │ 检索复盘       │
│ 当前工作区                │ └──────────────────────────────┘ │ 工具结果       │
│ [加入资料]                │ [输入框]                        │ 对比回答       │
│ 线程                      │ [+] [快捷工具] [回答引擎] [发送]│                │
│ [搜索线程]                │                                  │                │
│ + 新建                    │                                  │                │
│ ● 第二阶段前端设计        │                                  │                │
│   资料导入问题            │                                  │                │
└──────────────────────────────────────────────────────────────────────────────┘
```

**关键交互**：
- 切换线程后重新加载该线程聊天记录（`GET /api/chat/messages?session_id=`）
- 点击 `库` 或聊天输入框 `+ -> 加入资料` 打开资料管理弹窗，不离开聊天主流程
- 发送问题后按钮进入 loading 状态，禁用重复提交，并显示“取消”按钮关闭当前 EventSource 流
- 来源不足时显示建议工具横条，用户点击才触发工具运行（不自动执行）
- 工具运行成功后，可一键引用 `tool_run_id` 到下一轮问答
- 回答通过 `/api/answer/stream` 的 SSE `token` 事件逐步渲染，完成后用 `done` 事件刷新来源、观察性和聊天记录
- 来源、检索复盘、工具结果和对比回答默认进入右侧依据抽屉，不占用中间对话主流程
- 移动端默认隐藏侧栏，只保留顶部菜单按钮；点击后以抽屉显示侧栏

**空状态**：暂无会话时显示"点击 + 新建会话开始问答"引导文案

**错误状态**：API 不可用时显示可恢复提示，说明下一步操作（检查服务 / 刷新）

## 4. 当前 1.x：库弹窗

**页面目标**：让用户先加入资料，再从已有资料中选择需要用于工作区聊天的内容。第一版不把资料库作为一级普通页面，也不承担问答主流程。

```text
┌──────────────────────────────────────────────────────────────────┐
│ [库弹窗] 管理资料                                      [关闭]     │
│ [加入库] [选择资料]                                               │
├──────────────────────────────────────────────────────────────────┤
│ 加入库                                                           │
│ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌────────┐ │
│ │ 文件     │ │ 文件夹   │ │ 笔记     │ │ 网页摘录 │ │ 更多来源│ │
│ └──────────┘ └──────────┘ └──────────┘ └──────────┘ └────────┘ │
│ [本次结果] 默认折叠；导入完成或失败后自动展开                    │
├──────────────────────────────────────────────────────────────────┤
│ 选择资料                                                         │
│ 左侧主侧栏切换为“选择工作区”                                      │
│ 右侧显示资料夹、资料列表、加载、错误和空状态                      │
└────────────────────────────────────────────────────────────────┘
```

**关键交互**：
- `加入库` 首屏只展示文件、文件夹、笔记、网页摘录和更多来源
- GitHub、Notion、Obsidian 等高级来源收进“更多来源”；后端未完整支持时只显示说明或复用现有导入事件，不伪造成功
- `ImportResultList` 默认折叠；有导入状态或错误时自动展开
- 点击 `选择资料` 后，主左侧侧栏切换为工作区列表；选择目标工作区不切换当前聊天工作区
- 当前后端仍以 `project_id` 为资料边界，第一版不显示“已连接到多个工作区”这类状态

**空状态**：无资料时提示先用“加入库”上传文件、文件夹、笔记或网页。

## 5. 当前 1.x 练习与 2.0 评估覆盖层

**页面目标**：能力保留，但不作为一级页面。第一版入口位于聊天输入框 `+ -> 练习与小测`，后续可复用旧评估组件作为聊天工具弹窗或抽屉。

```text
┌────────────────────────────────────────────────────────────────┐
│  [聊天工具] 练习与小测                                [关闭]    │
├────────────────────────────────────────────────────────────────┤
│   当前工作区：知识岛 Web MVP       [开始练习]                   │
│   上次结果：已掌握 3 / 基本理解 2 / 需补充 1                   │
├────────────────────────────────────────────────────────────────┤
│  [题目区]                                                       │
│   第 2 / 5 题                                                   │
│   ─────────────────────────────────────────────────────────── │
│   请描述 RAG 混合检索的流程，以及关键词检索和向量检索如何合并。 │
│   ─────────────────────────────────────────────────────────── │
│   [答案输入框（多行）]                                          │
│                                                                 │
│   [跳过]                              [提交回答]               │
├────────────────────────────────────────────────────────────────┤
│  [练习结果]（提交后显示）                                       │
│   🟡 基本理解    参考来源：docs/design/search.md § 3           │
│   补充说明：回答提到了关键词检索但未说明得分合并策略           │
│   [继续追问]              [下一题 →]                           │
├────────────────────────────────────────────────────────────────┤
│  [错题记录]  ▼ 展开                                             │
│   • 向量化降级策略（暂未掌握）— 下轮优先复测                   │
└────────────────────────────────────────────────────────────────┘
```

**当前实现**：Web 前端已支持一轮多题评估的进度展示、逐题提交、单题反馈、答题记录和待复测列表；跨刷新持久化的错题复测入口仍待后续任务细化。

**2.0 目标**：评估可按知识点或技能节点发起；作答前不显示评分依据，提交后显示状态、置信度、命中证据、缺失点与来源。状态统一为 `unassessed / needs_work / developing / mastered`，并明确它只描述当前项目中的表现。

**空状态**：项目无文档时提示"请先打开库加入资料，再开始练习"

## 6. 当前 1.x 设置页与 2.0 增量

**页面目标**：全屏管理回答方式、资料保存、备份恢复和外观；技术字段默认收进详情。

```text
┌────────────────────────────────────────────────────────────────┐
│  [顶部导航栏]                                                   │
├────────────────────────────────────────────────────────────────┤
│  [返回] 设置                                                    │
│  [左侧菜单] 回答 / 资料 / 外观                                  │
├────────────────────────────────────────────────────────────────┤
│  [回答] 本机回答 / 本机快速 / 在线回答                          │
│        [连接详情] 服务地址、模型名、Key 引用、保存和测试          │
├────────────────────────────────────────────────────────────────┤
│  [资料] 资料保存位置 / 备份 / 恢复                              │
├────────────────────────────────────────────────────────────────┤
│  [外观] 深色模式 / 回答方式 / 依据显示                          │
└────────────────────────────────────────────────────────────────┘
```

**关键交互**：
- 测试连接不改变配置，仅验证可达性
- API Key 回显只显示来源引用（`env:DEEPSEEK_API_KEY`），不显示明文
- 每次只展示左侧菜单选中的一个设置页面，不做长滚动设置页
- 当前后端未提供完整资料保存位置迁移、备份恢复桌面能力时，按钮必须显示清楚的不可用或后续支持状态，不伪装成功

2.0 在保持全屏设置结构的前提下增加 Obsidian 连接、输出目录、令牌撤销和同步状态；高级检索、模型比较与 Agent 审计继续收在高级区域。

## 7. 空状态与错误状态约定

| 场景 | 展示文案 | 下一步引导 |
|------|----------|------------|
| 未创建项目 | "尚无项目空间" | 跳转设置页创建 |
| 项目无文档 | "知识库为空" | 打开库弹窗加入资料 |
| 检索无命中 | "未找到相关来源" | 建议换关键词或补充资料 |
| API 不可用 | "本地服务暂时不可访问" | 提示刷新或检查 `app.py` |
| 在线回答未配置 | "未配置在线回答，使用本地片段回答" | 打开设置页配置连接 |

## 8. 2.0 目标验收

1. 一级入口顺序和命名固定为 `教练 / 学习地图 / 学习计划 / 资料 / 设置`。
2. 教练保留聊天主区和依据抽屉，学习地图与学习计划不做成管理后台式彩色数据大屏。
3. 评估只以覆盖层或抽屉出现，关闭后保留原页面、输入和当前项目。
4. 项目理解、知识覆盖、技能差距、评估结果和计划阅读项都能打开真实来源。
5. Obsidian 当前一次性导入与 2.0 插件连接使用不同状态文案；未连接、离线、冲突和已撤销不得显示为成功。
6. 发布到 Obsidian 前必须预览内容和路径并显式确认；无系统标记、哈希变化或越界路径必须显示冲突并停止覆盖。
