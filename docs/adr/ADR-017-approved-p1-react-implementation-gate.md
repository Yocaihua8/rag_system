# ADR-017 以批准的 P1 Revision 3 启动 React 实施

> 状态：Accepted
> Date：2026-08-02
> Owner：RAG 团队
> Scope：P1/P2 原型门禁、B-175 React 开工授权与后续阶段边界
> Related：`ADR-012-agent-product-and-permissions.md`、`ADR-014-react-typescript-frontend.md`、`../design/ui-prototype-brief-v3.md`、`../guides/v3-upgrade.md`

## 1. 背景

ADR-012、ADR-014 和 v3 迁移指南原先要求先完成独立 P2 高保真原型并获得明确批准，再创建 `frontend-v3/`。P1 Revision 3 完成任务、工作流与设置作用域修正后，用户于 2026-08-02 明确指示“可以按照这份原型进行实现”。继续要求另一份独立 P2 交付会与这条最新实施授权冲突。

B-178 的后端与本地 P1 验收已经完成，但 Sites 生产发布仍因 `list_sites` 传输错误阻塞。这个外部发布问题不应丢失，也不应继续占用唯一 `doing` 计划并阻止已获授权的 Web 前端基础实施。

## 2. 决策结论

1. P1 Revision 3 视为已明确批准，并作为 B-175 React 生产前端的实施基线。
2. 创建 `frontend-v3/` 前不再要求单独交付一份 P2 原型；原 P2 的三种主题、视觉 token、文案、键盘、响应式和危险动作验收并入 B-175 的实现验收。
3. 本次授权只解除 B-175 的开工时间门禁，不自动授权 B-176 的完整业务联调、B-177 的目录切换、旧 Vue 删除、Tauri/Docker 切换或正式发布。
4. `frontend-v3/` 与现有 Vue 平行存在；B-175 不修改 Vue 页面，不改变根生产脚本、Tauri 或 Docker 指向。
5. 生产前端不得复制原型演示数据。后端尚未提供的 Settings、Sources、Insights、任意工作流执行、导出和桌面安全能力必须显示真实空态、不可用原因或隐藏入口，不能用假接口或本地业务规则冒充。
6. B-178 转为 `Interrupted`/`blocked` 并完整保留 Sites 恢复步骤；B-174 保持桌面令牌、存储、备份恢复等 `todo` 范围；B-175 成为唯一 `doing` 计划。

## 3. 决策原因

- 最新用户指令已经明确授权按当前原型实施，继续把独立 P2 当作开工前置会违背当前意图。
- 把高保真验收并入独立 React 目录，仍可在不影响 Vue 的前提下验证主题、响应式和可访问性。
- 将 Sites 阻塞与 React 实施分区，可以保留未完成的生产发布义务，同时避免外部连接问题冻结本地工程工作。
- 限定授权只覆盖 B-175，防止“可以实现”被扩大解释为最终切换或删除旧实现。

## 4. 影响

### 4.1 被本 ADR 部分取代的内容

- ADR-012 中“P2 明确批准后再解除 React 前端实施门禁”的时间门禁。
- ADR-014 中“P2 前禁止创建 `frontend-v3/`”以及相同含义的实施开始条件。
- v3 UI 简报与迁移指南中要求独立 P2 交付先于 React 目录创建的顺序。

React 技术栈、前后端状态边界、Vue 平行保留、真实后端验收和最终切换门禁继续有效。

### 4.2 风险

- 高保真决策进入实现阶段后，视觉调整可能产生代码返工。
- 当前 v3 API 已补充按 Task 查询运行历史；仍缺少 Settings、Sources、Insights、导出与可执行自定义工作流，第一阶段页面必须明确能力边界。
- 桌面令牌、存储预检、备份和受控恢复后端已经完成，但平行 React 前端尚未接入这些操作，界面仍需保持真实不可用边界。

## 5. 验证方式

- `frontend-v3/` 使用独立 workspace，现有 `frontend/`、Tauri 和 Docker 入口保持不变。
- OpenAPI 类型来自 `/api/v3/openapi.json`，生产运行逻辑不含演示数据回退。
- 当前独立 workspace、四个一级页面、生成类型和固定项目检查闭环已经建立；工作流编辑、资料/洞察、导出及桌面运维仍保持不可用，不能据此扩大到 B-176/B-177。
- B-175 完成前通过 typecheck、Vitest、React Testing Library、构建、主题、键盘和 320px–桌面响应式验收。
- B-176/B-177 开始前仍需按各自计划确认真实 API、Desktop 和最终切换门禁。

## 7. 执行结果

用户于 2026-08-03 明确确认前端验收，B-175 的高保真门禁完成。该结果冻结当前平行 React 的视觉与交互基线，但不改变本 ADR 对完整联调、正式入口切换、Vue 删除和发布动作的独立授权边界。

## 6. 回滚

删除尚未切换的 `frontend-v3/` workspace，并让根脚本继续只编排现有 Vue 与 Tauri 即可回滚；不涉及业务数据迁移。B-178 Sites 阻塞记录和 v3 后端不受影响。
