# 功能模块说明

> 状态：Active
> Owner：RAG 团队
> Last Updated：2026-08-01
> Scope：用户可感知能力及其边界
> Related：`project-background-and-scope.md`、`use-cases.md`、`../features/README.md`、`../design/api-spec.md`

本文件按用户任务划分功能，不按 Vue、FastAPI、Tauri、Docker 或插件等技术组成拆专题。可达页面、兼容源码和未实现内容必须分别判断。

## 1. 项目与资料

用户可以创建和选择项目，并把受支持的本地或显式网络来源导入当前项目。系统保存文档、分块、向量兼容副本、集合和导入批次；所有读写按 `project_id` 隔离。

当前边界：

- 资料弹窗可达笔记、文件、文件夹、GitHub 仓库和 Obsidian Vault 等入口。
- URL 摘录后端要求 `url`、`title`、`content`，当前弹窗只提交 `url`，因此该可见入口尚不能完成导入。
- 单 URL 网页抓取是独立受控流程；预览会联网并执行公网地址、重定向、`robots.txt`、大小和内容类型限制，提交阶段不重新联网。
- Obsidian Vault 导入是一次性只读导入，不建立插件连接，也不表示双向同步。
- 文档集合只组织文档，不复制内容；删除集合不删除文档。

## 2. 检索、问答与聊天

系统对文档分块后执行 BM25 关键词与向量混合检索；可选 Qdrant 提供向量候选，失败时回退 SQLite。问答优先使用配置的模型，不可用时回退为来源片段组合回答。

当前边界：

- 教练主视图通过 SSE 渲染回答，并在完成后展示来源和聊天记录。
- 没有命中时不得伪造来源；只可提示换关键词、补充资料或手动运行只读检索工具。
- 会话、分支消息、反馈、模型对比、检索调试/复盘和 Agent 审计均有后端能力；高级能力位于依据区，不是独立主导航。
- 资料选择界面存在，但当前提问请求没有把所选资料集合或文档作为过滤条件传给后端。

## 3. 项目分析与学习地图

项目分析从当前已导入资料生成项目概览、稳定知识点、来源证据和版本化技能映射。学习地图展示项目知识覆盖、技能辅助映射和最近评估。

当前边界：

- 项目知识覆盖是主口径，技能状态只从当前项目有关联证据的知识点聚合。
- 来源变化可使分析变为 `stale`；历史结果仍可只读追溯，但不能作为最新结果发起新评估或逐点学习。
- 结构化分析优先覆盖 Python、JavaScript/TypeScript 和常见 Web 项目；其他文本项目使用通用回退。
- 系统不输出职业等级、跨项目总分或岗位胜任力。

## 4. 定向评估

用户可从知识点或技能节点发起评估。系统持久化评估会话、题目、回答、评分方式、分数、置信度、命中证据、缺失点和来源。

状态统一为：

| 状态 | 含义 |
|------|------|
| `unassessed` | 没有有效评估证据 |
| `needs_work` | 得分低于 `0.50` |
| `developing` | 得分不低于 `0.50` 且低于 `0.75` |
| `mastered` | 得分不低于 `0.75` |

作答前不返回服务端评分要点。模型评分不可用时可以回退规则评分；结果只代表当前项目与当前来源版本。旧 `/api/assessment/*` 和未挂载的兼容组件仍保留，但当前主闭环使用 Coach 评估接口和覆盖层。

## 5. 逐知识点交互学习

用户可从教练、学习地图知识点或技能节点、已确认学习计划的 `learning` 任务启动或恢复学习会话。会话绑定当前分析运行，一次只展示一个知识点和一道题，并持久化每次 attempt、评分、反馈和来源版本。

当前边界：

- 会话状态为 `ready / learning / awaiting_answer / evaluated / retrying / completed / abandoned`；来源过期或进入终态后只读。
- 每个知识点最多三次 attempt，达标阈值为 `0.75`；答案揭示后的同题作答只用于练习，不形成独立掌握证据。
- 当前覆盖同时读取 Coach 评估结果和有效学习 attempt；旧来源版本的 attempt 只保留历史记录。
- 只有从确认计划任务启动的会话自动推进该任务，打开会话不改变进度，首次完成评分推进为 `in_progress`，全部步骤有效达标后推进为 `done`。
- SQL 练习只由当前项目可解析 SQLite Schema 证据触发。来源 DDL 只解析为结构化 fixture；学习者查询只在独立临时只读数据库中执行，不连接正式应用数据库。
- 首版只允许一条只读 `SELECT` 或非递归 `WITH ... SELECT`，不提供 DML、DDL、在线 SQL 课程或任意项目数据库查询。

## 6. 学习计划

系统依据当前分析和评估生成学习计划草稿。任务可包含学习目标、关联知识点或技能、真实来源、练习问题、完成标准、预计时长和状态。

当前边界：

- 草稿可以编辑结构、排序并确认；已确认计划结构不可原地改写，只允许更新任务进度。
- 重新生成创建新修订，不覆盖已确认计划。
- 有来源的 `learning` 任务必须引用当前项目真实来源；缺少来源时只能生成明确的 `source_gap` 任务。
- 计划不提供日历排期、提醒、证书或自动执行。

## 7. Obsidian 连接与发布

独立桌面插件通过一次性配对码连接当前项目，发送 Markdown 的 `upsert`、`rename`、`delete` 事件，并领取用户已确认的发布任务。

发布状态遵循“预览 → 确认 → 排队 → 插件执行 → 回传终态”：

- 浏览器确认只表示 `queued`，不表示 Vault 已写入；
- 插件只在配置的输出根内处理受管 Markdown；
- 管理标记缺失、路径越界或 hash 冲突时拒绝覆盖；
- 发布修订不可变，插件回传 `applied`、`conflict` 或 `failed` 后才形成终态。

服务端只保存配对码和连接令牌哈希；插件为离线恢复会在当前 Vault 的插件数据中保存令牌明文，因此 Vault 文件系统权限也是安全边界。

## 8. 设置与诊断

- LLM 全局设置、模型 Profile、项目 Prompt 预设和 Obsidian 连接已接入当前设置页。
- Profile 的 SQLite 记录只保存受控 Key 引用；兼容全局设置接口接收 Key 后会把明文写入用户应用数据目录的 `.env`，但读取接口不回显明文。
- 资料位置、备份/恢复和外观按钮目前为禁用或说明状态；对应后端能力存在并不等于设置页已接入。
- 可选共享 API Key/JWT 认证由后端实现，但当前 Vue `fetch` 和 `EventSource` 没有凭证装配；当前主界面只承诺默认关闭认证的本地模式。

## 9. 运行形态

- 本地开发：Vue 开发服务和 FastAPI API 独立启动。
- Web/Docker：前端静态服务与后端 API 分为两个服务，前端不反向代理 API。
- Tauri：WebView 打包前端产物，sidecar 只承载后端；不复制业务逻辑。
- Obsidian：插件独立安装、构建和鉴权，不进入根 npm workspace。

运行形态不改变 HTTP 字段、SQLite Schema 或产品状态机。可执行命令见 [`../guides/README.md`](../guides/README.md)。
