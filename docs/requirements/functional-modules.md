## 3. 项目与来源

### 3.1 目标能力

- 在 `runtime/v2/` 中从零创建项目，所有资料、分析、评估、计划和 Obsidian 连接按 `project_id` 隔离。
- 导入代码目录、项目文档、笔记和现有支持来源，并保存可追踪的来源标识与内容版本。
- 来源新增或修改后使相关分析过期；重命名保留映射；删除清理对应索引并使相关结论过期。

### 3.2 边界

- 不支持跨项目资料共享、全局资料库或跨项目评价。
- `POST /api/import/obsidian-vault` 继续是一次性只读导入，不代表插件同步。
- 系统生成的 Obsidian 输出目录不得作为输入再次摄入。

## 4. 项目分析

### 4.1 目标能力

- 生成有来源的项目概览、知识点和知识点—技能映射。
- Python、JavaScript / TypeScript 和常见 Web 清单使用首批结构化规则。
- 其他文本项目使用目录结构、清单、README、设计文档、测试路径和 RAG 通用回退。
- 无 LLM 时提供规则基线；有 LLM 时增强摘要和提炼，但保留同等来源约束。

### 4.2 边界

- 没有来源的项目事实不得进入正式结果。
- 不构建全语言 AST、完整调用图或 IDE 级代码导航。
- 来源变化后旧分析标记为 `stale`，不得当作最新状态展示。

## 5. 教练问答

### 5.1 目标能力

- 默认“教练”复用当前工作区会话、流式回答和依据抽屉。
- 回答、来源和教练工具始终限定在当前项目。
- 资料不足时明确说明缺口，并引导补充资料或重新分析。

### 5.2 边界

- LLM 可选；无 LLM 时保留本地检索聚合回退。
- 高级检索、模型比较和 Agent 审计不作为首页主线。
- Agent 工具保持只读，不执行 shell 或写入项目文件。

## 6. 项目评估

### 6.1 目标能力

- 从知识点、技能节点或聊天工具入口发起可恢复的评估会话。
- 作答前只返回题目和必要上下文，不返回评分要点。
- 作答后保存 `rule|model` 评估方式、分数、置信度、命中证据、缺失点和来源。
- 状态统一为 `unassessed / needs_work / developing / mastered`，阈值依次为未评估、`<0.50`、`0.50–0.74`、`≥0.75`。

### 6.2 边界

- 结果只代表当前项目和当前来源版本，不代表整体技术水平。
- 模型评估必须保留来源；模型不可用时回退到规则评估。
- 现有 `/api/assessment/*` 继续保留，新闭环使用 Coach 评估接口。

## 7. 学习地图

### 7.1 项目知识覆盖

- 项目知识覆盖是主评价口径，按知识点展示状态、最近评估和来源。
- `unassessed` 与低分状态必须分开，避免把“未验证”误写为“不会”。

### 7.2 通用技能树

- 首版技能域包括语言、框架、数据、测试、交付和 AI，并使用版本化定义。
- 技能状态只从已关联项目知识点聚合，必须可回溯到映射证据。
- 技能树只辅助组织学习，不输出职业等级、JD 匹配、跨项目总分或个人排名。

## 8. 学习计划

### 8.1 目标能力

- 根据当前知识覆盖与技能差距生成计划草稿。
- 每个任务包含目标、知识点或技能、阅读来源、练习问题、完成标准、预计时长和状态。
- 草稿可编辑和排序；用户确认后形成独立版本。
- 重新生成只产生新草稿，不覆盖已确认计划。

### 8.2 边界

- 计划只引用当前项目的真实来源；缺少来源时必须明确标记补充资料任务。
- 不提供日历排期、提醒、自动执行或学习证书。
- 计划确认不触发 Obsidian 写回，发布仍需单独预览和确认。

## 9. Obsidian 桥

### 9.1 目标能力

- 独立桌面插件通过一次性限时配对码连接本地服务；每个项目最多一个活动连接。
- 插件发送 Markdown 的 `upsert / rename / delete` 幂等事件，以及 Frontmatter、标签、已解析和未解析 Wikilink。
- 发布按“预览 → 用户确认 → 插件执行 → 结果回传”进行，并保存不可变修订。
- 默认输出到 `Knowledge Island/<项目名>/`，目标目录可在配对时配置。

### 9.2 边界

- 服务端只保存令牌哈希，令牌仅能访问 Obsidian 路由并可撤销。
- 只有带 `knowledge_island_managed` 和稳定标识的系统文件可更新。
- 哈希变化、无管理标记或路径越界时必须停止覆盖；首版不自动合并。
- 不支持移动端插件、社区市场发布、云同步或后台无确认写回。

## 10. Vue 信息架构

一级入口目标为：

1. **教练**：会话、学习问答、评估入口和依据抽屉。
2. **学习地图**：项目理解、知识覆盖、技能差距和评估记录。
3. **学习计划**：草稿编辑、确认、Obsidian 发布预览和冲突处理。
4. **资料**：当前项目资料、导入和 Obsidian 连接状态。
5. **设置**：模型、Obsidian 连接、输出目录、令牌撤销、同步状态和高级能力。

现有 Codex 风格视觉、工作区侧栏、会话、资料弹窗和依据抽屉继续作为外壳。评估使用抽屉或覆盖层，不恢复管理后台式独立页面。

## 11. 跨模块不变量

- 所有教练数据按项目隔离，不产生跨项目隐式聚合。
- 所有结论必须有来源；模型推断不能替代来源事实。
- 2.0 只使用 `runtime/v2/`，旧运行时数据保持不变。
- LLM 失败不得阻断规则基线闭环。
- 已确认计划和已发布修订不可被重新生成或同步事件静默覆盖。
- Obsidian 写回始终由用户显式确认，且只能发生在授权目录和系统管理文件内。

## 12. 非目标

- 多用户与团队权限、跨设备或云端同步。
- 全局资料库、跨项目能力总览或跨项目问答。
- 职业等级、求职评价、绩效考核或 JD 匹配。
- 完整静态分析平台、IDE、Agent 编码或命令执行。
- Obsidian 移动端、社区市场发布和自动合并冲突。
