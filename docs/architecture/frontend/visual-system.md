# Codex 风格前端视觉规范

> 状态：Active
> Owner：RAG 团队
> Last Updated：2026-07-23
> Scope：Knowledge Island 当前项目知识教练与 1.x 兼容能力的桌面优先视觉语言、组件状态与动效边界；不改变 API、数据库或业务行为。
> Related：docs/architecture/frontend/pages.md, docs/architecture/frontend/workspace-experience.md, docs/product/features/frontend-engineering.md, frontend/src/styles/tokens.css, frontend/src/styles.css

## 1. 目的与边界

本规范以 Codex 的清晰、低干扰、会话优先体验为参考，为 Knowledge Island 定义可持续复用的视觉语言。参考的是信息层级和交互克制性，不复制 Codex 的品牌资产、图标或页面细节。

视觉目标：

- 让当前用户先看到当前项目、教练上下文和下一步学习动作，同时保留 1.x 导入与聊天兼容能力。
- 将资料管理、回答依据、评估和高级工具收进按需出现的区域。
- 用中性界面承载内容，避免让颜色或装饰与资料阅读竞争注意力。

实现边界：

| 代际 | 已实现或待验收 | 视觉约束 |
|------|--------------|----------|
| 1.x 兼容能力 | 原有导入、聊天、回答依据和旧评估 API / View 继续保留 | 不把兼容页面恢复成主导航，不伪装跨项目资料能力 |
| 当前 2.0 Vue 闭环 | 一级入口为 `教练 / 学习地图 / 学习计划 / 资料 / 设置`，定向评估和发布预览为覆盖层 | 复用本规范的中性色、低干扰层级；发布确认后显示 `queued` 并等待插件执行 |

本规范本身不新增功能。资料继续按 `project_id` 隔离；B-157“全局资料库 / 跨工作区共享”不再推进，界面不得用全局连接状态暗示该能力存在。

## 2. 信息层级与布局

| 层级 | 区域 | 视觉职责 | 默认状态 |
|------|------|----------|----------|
| 一级 | 项目与主导航侧栏 | 定位当前项目；展示教练、学习地图、学习计划、资料、设置 | 桌面端展开；窄屏隐藏为抽屉 |
| 二级 | 当前任务主区 | 按入口承载教练会话、学习地图或学习计划 | 始终可见，优先占用剩余空间 |
| 三级 | 依据抽屉 | 来源片段、知识点来源、来源不足提示、只读工具结果 | 默认收起，按需打开 |
| 覆盖层 | 资料弹窗、评估、发布预览、设置页 | 完成短流程、确认写回或集中配置 | 仅由显式操作打开 |

- 侧栏收起必须完全移出布局，不保留品牌窄栏或空白占位；顶部菜单按钮负责恢复。
- 主区不得因为资料弹窗或设置入口而压缩成管理后台式多列页面。
- 抽屉、弹窗与设置页应覆盖或附着于当前上下文，关闭后回到原会话，不重置用户输入和已选工作区。

## 3. 设计令牌

令牌以 `frontend/src/styles/tokens.css` 为单一实现来源。本表定义语义，不要求在本次文档任务中修改 CSS。

| 类别 | 令牌 / 当前值 | 用途 |
|------|---------------|------|
| 页面底色 | `--surface-page` / `#f7f7f7` | 应用背景、设置覆盖页背景 |
| 内容表面 | `--surface-card` / `#ffffff` | 侧栏、卡片、抽屉、弹窗主体 |
| 选中与悬停 | `--surface-hover` / `#eeeeee` | 当前导航、当前工作区、轻量悬停反馈 |
| 主文字 | `--text-primary` / `#111111` | 标题、正文、主操作 |
| 次文字 | `--text-secondary` / `#666666` | 描述、计数、辅助信息 |
| 分隔 | `--border` / `#dddddd` | 面板边界、列表分组、输入框边界 |
| 主操作 | `--accent` / `#111111` | 黑底白字的确认与发送操作 |
| 风险状态 | `--danger`、`--warning` | 仅用于错误和需要注意的结果，不作为品牌色 |
| 间距 | `--space-1` 至 `--space-7` / 4–48px | 采用既有 4px 递进，避免临时任意值 |
| 圆角 | `--radius-sm`、`--radius`、`--radius-lg` / 6、8、12px | 低圆角、克制分组，不使用胶囊化大卡片堆叠 |
| 动效 | `--dur-fast` 120ms、`--dur-base` 200ms | 仅用于确认操作与层级切换 |

深色模式沿用同名语义令牌的深色值；组件禁止在新增样式中直接写另一套品牌色，除非是错误、警告或可访问性修复。

## 4. 组件规则

| 组件 | 规则 | 禁止事项 |
|------|------|----------|
| 主导航与列表项 | 透明底为默认态，当前项使用浅灰底与深色文字；图标只辅助文字理解 | 用多色图标区分普通导航，或把所有入口做成强调按钮 |
| 主按钮 | 黑底白字，仅用于发送、确认等单一主操作；同一视图最多一个视觉主按钮 | 在一个区域并列多个黑底按钮 |
| 次按钮与图标按钮 | 白底或透明底、浅灰边框；必须有可见文字或无障碍名称 | 只用不具说明的符号承载关键业务动作 |
| 输入框 | 问题输入优先占据会话末端；工具、回答引擎与发送围绕输入框组织 | 将检索参数、模型参数、导入统计直接铺进输入区 |
| 资料弹窗 | 只承载“添加资料”与“选择资料”短流程；结果按已加入、已更新、已跳过、失败分组 | 伪造实时进度、跨工作区连接成功或后台同步状态 |
| 依据抽屉 | 默认收起，标题和来源路径优先于技术参数；高级信息按需展开 | 把 `chunk`、向量分数或 `top_k` 置于普通首屏 |
| 学习地图 | 用清晰分组展示项目理解、知识覆盖和辅助技能差距；状态必须同时有文字 | 做成职业评分榜、雷达图装饰墙或管理后台统计大屏 |
| 学习计划 | 以可编辑、可排序任务列表为主体，明确草稿与已确认状态 | 用重新生成静默覆盖已确认计划 |
| 评估覆盖层 | 保留进入前页面上下文，题目作答前不展示评分依据，结果可查看来源 | 将评估恢复成一级管理页面，或把项目评估包装为整体职业能力 |
| Obsidian 发布预览 | 同时展示目标路径、内容摘要、冲突和确认动作 | 自动覆盖无系统标记、哈希变化或越界路径的笔记 |
| 设置页 | 全屏覆盖，左侧菜单一次选择一个设置分组，右侧展示对应内容 | 长页面堆叠所有配置，或回显访问密钥明文 |
| 空状态与错误 | 用一句当前状态加一个可执行下一步说明 | 仅展示错误码、使用装饰性插画掩盖不可用能力 |

## 5. 字体、内容密度与文案

- 使用既有无衬线字体栈 `--font-sans`；代码、路径和参数仅使用 `--font-mono` 的等宽上下文。
- 正文以 14px 为基准，辅助信息可降至 12–13px；不要依靠过小字体塞入更多管理信息。
- 标题用于定位内容，描述只说明下一步，不重复解释技术原理。
- 普通界面优先使用“工作区”“添加资料”“回答依据”“回答引擎”“工具”；一级入口固定使用“教练”“学习地图”“学习计划”“资料”“设置”。`project_id`、`session_id`、RAG、Chunk、Prompt 等仅出现在开发或高级上下文。
- 当前已实现界面仍有“线程”文案；若后续统一为“会话”，必须在同一前端文案任务中同步 `ui-wireframes.md`、功能规格与测试断言，不能只改设计稿。

## 6. 动效与可访问性

- 按钮反馈约 100–150ms；菜单、侧栏和依据抽屉约 160–220ms；弹窗与设置页约 180–240ms。
- 动效只用于确认操作、展示层级变化和减少突然跳变。回答流式输出保持自然追加，不叠加逐字跳动等装饰。
- 必须支持 `prefers-reduced-motion`：降低时长或关闭非必要过渡。
- 键盘必须可以打开、关闭和返回侧栏、资料弹窗、依据抽屉与设置页；可见焦点不得被中性色边框吞没。
- 深色模式、错误、警告和选中态都不能只依赖颜色表达状态；同时提供文字、图标或位置提示。

## 7. 设计验收

视觉或前端实现切片应至少人工核对：

1. 收起侧栏后主区获得完整宽度，顶部菜单可恢复侧栏。
2. 会话输入区、发送按钮与当前回答在首屏可辨，资料管理与高级工具不抢占主区。
3. 当前选中态、主按钮、次按钮、错误和警告具有稳定且可区分的层级。
4. 依据抽屉和资料弹窗关闭后保留会话上下文，不产生虚假的完成或同步状态。
5. 窄屏只优先显示会话主区，侧栏与依据以抽屉方式按需出现。
6. 开启减少动态效果时，页面仍可理解且没有影响操作的位移。
7. 2.0 页面沿用同一套中性令牌；学习地图、学习计划和评估不退化为彩色数据看板。
8. Obsidian 写回必须经过预览与确认；冲突不能只依赖颜色表达，也不能出现自动覆盖动效。
